# 8. References and resource management

This clause defines the reference system: tribes, modifiers, the chain rules, routes, reference forms, the propagation of object lifetime, atomic references and ordering fences, unmanaged reference arithmetic, the compare-and-swap operator, the copy and transfer of values, and destructors.

A **reference** is a value that designates an object. The **referent** of a reference is the object that the reference designates. Every reference has a referent type. That of a slice reference is defined in §8.2.5, and that of any other reference is the type the tail of its reference type denotes.

## 8.1 Reference properties

### Syntax

```
ref_type     = ref_base, type ;
ref_base     = ref_tribe, ws, { ref_modifier, ws } ;

ref_tribe    = '%' | '&' | '$' ;
ref_modifier = "volatile" | "atomic" | "mut" ;
```

The character that leads a reference type is its **tribe**.

### Static semantics

#### Tribes

&mdash; **Shared reference** (`&`) &mdash; a managed reference that the chain rules (§8.1.1) treat as shared.

&mdash; **Exclusive reference** (`$`) &mdash; a managed reference that the chain rules treat as exclusive.

&mdash; **Unmanaged reference** (`%`) &mdash; a reference that carries no object lifetime and is derived from nothing.

A reference whose tribe is `&` or `$` is a **managed reference**.

#### Modifiers

&mdash; Volatile access (`volatile`) &mdash; every access through a reference carrying `volatile` is a σ operation (§2.5).

&mdash; **Store permission** (`mut`) &mdash; a reference without `mut` permits loads alone, and one carrying it permits stores through the reference as well. An access through a shared reference carrying `mut` requires airside, unless the reference carries `atomic`.

&mdash; Unordered atomic access (`atomic`) &mdash; every access through a reference carrying `atomic` is performed as §8.4 defines.

#### Uncopyable references

An exclusive reference is uncopyable.

### Constraints

Each constraint of this clause upon a reference type applies to one that is written and to one that an expression forms.

The type of a `const` declaration, of an implanted constant, and of a `const` block shall be copyable. A type that is or has as a constituent an exclusive reference type shall be neither the type of a `static` declaration nor the referent type of a shared reference.

For a type, an expression, or a block item, the static semantics and the constraints of this clause hold under every eligible resolution (§4.10) of the type parameters that occur free in it or in a type or an expression within it, except the constraint upon the type of a `static` declaration and upon the referent type of a shared reference. That constraint holds in semantic analysis (§10.2), where a type parameter neither is nor has as a constituent an exclusive reference type.

### Design rationale (informative)

Were an exclusive reference copyable, `let a: $si4 = $x; let b = a;` would produce two mutually underived exclusive references to one object.

The tribes and the chain rules prevent unintended behaviour by recording, during translation, how one reference is derived from another. They constrain what the Kurt source text writes. Which cells an access spans, and whether two accesses span a cell in common, are settled by the object model of §2.2.4.

```
#extern io {
    variadic fn printf(%ui1) -> si4;
}

fn poke(x: &saddr) {
    airside { instruct { str '(1), ['p] } with { in('p) = x; } }
}

pub fn reflicate[T](a: %T) -> .{ $mut T, $mut T } {
    airside {
        return .{ a as $mut T, a as $mut T };
    }
}

fn main() -> ui1 {
    let mut x: saddr = 0;
    poke(&x);                                // x holds 1
    airside { io::printf("%d\n\0".ptr, x); } // prints 1

    let .{ p, q } = reflicate[saddr](%x);    // both designate x
    *p = 2;
    *q = 3;
    airside { io::printf("%d\n\0".ptr, x); } // prints 3
    return 0;
}
```

The programme violates no rule of this specification. `poke` performs a store no reference form permits; `reflicate` produces, without leaving the Kurt source text, the arrangement that the uncopyability of exclusive references prevents that text from writing.

### 8.1.1 Derivation chain

#### Static semantics

The rules of this subclause, of §8.1.2, and of §8.3 are the **chain rules**. On a trace of a frame, a programme point (§2.1) means one visit to it; visit *t* is the *t*-th on the trace, counting from zero. Each creation, each invocation, each load from an immortal object, and each construct whose value crosses (§6.11) yields, at each visit, references distinct from those it yields at every other visit. (*I*(*t*) ∩ *I*(*t*′) = ∅ for visits *t* ≠ *t*′ of one such construct, *I*(*t*) the references it yields at *t*)

Every chain rule holds in every choice of one reference from each set of references that a base, a position, or a result may be, or that an object may hold. Only the rules below on referents and on what objects keep relate the references of one choice. For the chain rules, the effect of an invocation is the union of the effects of the bodies that conform to the signature of the invoked subroutine. (effect(*c*) = ⋃{effect(*B*) | *B* conforms to the signature of *h*}, *c* an invocation of *h*)

Write *t* for a point of a frame, des(*r*) for the possible referents of a reference *r*, ref(*q*) for the reference at a position *q*, *r* ∈ *Z* where *r* is unchained, and excl(*r*) where *r* is exclusive. Write *a* ⋒ *b* where *a* and *b* may overlap, *b* ⊑ *e* where *b* is *e* or is derived from *e* in every choice, left(*v*, *o*) where the frame leaves *v* in *o*, and leaked(*v*) where it leaks *v*. Write born(*e*) for the point at which a reference *e* is made (for a reference at a position of the body, the start of the frame), and last(*e*) for the last use of *e* or of a reference that may be derived from *e*. ↦ is the routes relation of the frame’s own signature, and ↦<sub>*h*</sub> that of a subroutine *h* it invokes. Positions, layers, stems, and what a frame leaves and leaks are as §8.1.2 defines them.

For the chain rules, a reference that an expression yields, or that an object of a reference type holds, is of the tribe and modifiers that the type of that expression or object states.

A **frame** is the body of one subroutine, or the evaluation of an evaluation root, checked alone against its own signature. An evaluation root has a signature with no parameter and no `routes` clause. For the chain rules, an evaluation root whose value initializes a permanent object (§2.2.6) stores, through no reference, the value that crosses into that object.

For the chain rules, the referents of the exclusive references at two distinct positions of the body are neither one object nor one a constituent object of the other. (*q* ≠ *q*′ ∧ excl(ref(*q*)) ∧ excl(ref(*q*′)) ⇒ ¬(*o* = *o*′ ∨ *o* a constituent object of *o*′ ∨ *o*′ a constituent object of *o*), *o* and *o*′ the referents of ref(*q*) and ref(*q*′), *q*, *q*′ positions of the body) Where the referent of the reference at a position of the body is the referent of the exclusive reference at another position, or a constituent object of it, the former reference is derived from the latter. (*q* ≠ *q*′ ∧ excl(ref(*q*′)) ∧ (*o* = *o*′ ∨ *o* a constituent object of *o*′) ⇒ ref(*q*) ⊑ ref(*q*′), *o* and *o*′ the referents of ref(*q*) and ref(*q*′), *q*, *q*′ positions of the body)

A **known object** is a mortal object (§2.2.6) of the frame, a constituent object (§2.2.4) of one, or an immortal object. The referent of the reference at a position of the body is no mortal object of the frame.

An object that is not a known object is **tethered** where it is the referent of an exclusive reference at a position of the body, or a constituent object of that referent. It is **untethered** where it is the referent of the reference at a position of the body, or a constituent object of that referent, and is not tethered. (teth(*o*) ⇔ *o* ∈ *D* ∧ *o* is, or is a constituent object of, the referent of ref(*q*) for a position *q* of the body with excl(ref(*q*)), and untethered(*o*) ⇔ *o* ∈ *D* ∧ ¬teth(*o*), *D* being the objects that are no known object and are, or are constituent objects of, the referent of ref(*q*) for a position *q* of the body)

Two objects, each a known object or a tethered object, overlap where they are one object or one is a constituent object of the other, and in no other case. (*a* ⋒ *b* ⇔ *a* = *b* ∨ *a* a constituent object of *b* ∨ *b* a constituent object of *a*, for *a*, *b* each a known object or an object *o* with teth(*o*)) An untethered object overlaps every immortal object and every untethered object, and no other object. (untethered(*a*) ⇒ (*a* ⋒ *b* ⇔ *b* an immortal object ∨ untethered(*b*)))

A load of an untethered object may yield the initial value of that load, a reference that an invocation has made from `static` before that load, or what the frame has left, before that load, in an untethered object, in an object of a reference type within a tethered object, or in an immortal object. (untethered(*o*) ⇒ yield(load *o* through *r* at *t*) ⊆ init(*r*) ∪ {*v* | *v* made from `static` by an invocation at a *t*′ &lt; *t*} ∪ {*v* | left(*v*, *o*′) at a *t*′ &lt; *t*, with untethered(*o*′), *o*′ of a reference type within a tethered object, or *o*′ an immortal object}) Through a reference whose stem is a layer of a parameter, that initial value is the reference at the next layer of that parameter, one for each stem and type of the reference loaded; through a reference whose stem is `static`, it is a reference that the load makes from `static`. (init(*r*) = {the reference at layer *k*+1 of `p`, one for each stem and type of the reference loaded} where stem(*r*) = `p.k`, and init(*r*) = {a reference that the load makes from `static`} where stem(*r*) = `static`)

The **possible referents** of a reference *d* are given by the one of the following that describes *d*:

&mdash; Made by the frame, through no reference, from a known object: that object. (des(*d*) = {*P*}, *P* that object)

&mdash; Made by an invocation or a load from `static`: every immortal object, every untethered object, each tethered object that the next sentence describes, and every constituent object of each of these. A tethered object is so described where it is a possible referent of a reference *v* whose stem is a layer of a parameter and, before *d* is made, the frame has leaked (§8.1.2) *v*, or an invocation has had *v* at a layer that the signature of the invoked subroutine routes to `static`. (des(*d*) = *E* ∪ {the constituent objects of *E*}, *E* being the immortal objects, the untethered objects, and each *o* with teth(*o*) and *o* ∈ des(*v*) for a *v* with stem(*v*) = `p.k` that, at a point before born(*d*), is leaked or is, at an invocation of an *h*, at a layer *λ* with *λ* ↦<sub>*h*</sub> `static`)

&mdash; Derived by the frame from a reference *r* by field selections: the constituent objects they select within the possible referents of *r*, and each possible referent of *r* in which they select nothing. (des(*d*) = des(*r*).*f̄* ∪ {*o* ∈ des(*r*) | *o*.*f̄* = ∅}, *f̄* the selections)

&mdash; Derived by the frame from a reference *r* by a re-reference, a cast, or a decay: the possible referents of *r*. (des(*d*) = des(*r*))

&mdash; Derived by an invocation from a reference *s* (§8.1.2): where *d* is a wide reference, the possible referents of *s* and each constituent object of one, and otherwise those of them whose type is the referent type of *d*. (des(*d*) = *C* for a wide *d*, and {*o* ∈ *C* | the type of *o* is the referent type of *d*} for any other *d*, *C* being des(*s*) and the constituent objects of its members)

&mdash; At a position of the body: its referent. (des(*d*) = {the referent of *d*})

A reference is **chained** where it is a managed reference and one of the following holds:

&mdash; `&expr` or `$expr` creates it from a value expression.

&mdash; The frame makes it, through no reference, from an object.

&mdash; The frame makes it from an object expression that reaches its object through a reference, and the reference nearest the object (§6.4.3) is chained.

&mdash; A cast or a decay makes it from a chained reference, or an invocation derives it from one (§8.1.2).

&mdash; It is at a position of the body.

&mdash; It is shared, and an invocation or a load makes it from `static`.

Every other reference is **unchained**. (*r* ∉ *Z* ⇔ *r* managed ∧ (*r* created by `&expr` or `$expr` from a value expression ∨ *r* made by the frame, through no reference, from an object ∨ *r* made by the frame from an object expression whose reference nearest the object is an *r*′ ∉ *Z* ∨ *r* made from an *r*′ ∉ *Z* by a cast or a decay ∨ *r* derived by an invocation from an *r*′ ∉ *Z* ∨ *r* = ref(*q*) for a position *q* of the body ∨ (¬excl(*r*) ∧ *r* made from `static` by an invocation or a load)))

Where the value of a construct crosses, for the chain rules the frame makes each managed reference that the crossed value is or holds, through no reference, from the least immortal object that is or contains its referent. (for a construct whose value *v* crosses and each managed *r* that the crossed *v* is or holds: *r* is made by the frame, through no reference, from *P*, *P* the least immortal object that is or contains the referent of *r*)

After a store through an unchained reference, every object holds what it held before.

The chain rules concern chained references and accesses made through no reference only.

In each choice, the referent of a reference is one of its possible referents, where it has any. (rf(*r*) ∈ des(*r*) in each choice where des(*r*) ≠ ∅, rf(*r*) the referent of *r* in that choice) The referent of a reference that the frame derives from a reference *r* by field selections, and the object that a load through *r* with those selections loads, are what those selections select within the referent of *r*, or that referent where they select nothing. (rf(*d*), for *d* derived by the frame from *r* by selections *f̄*, and the object a load through *r* with selections *f̄* loads, are rf(*r*).*f̄* where *f̄* selects in rf(*r*), and rf(*r*) where it selects nothing) A reference that the frame derives from a reference *r* by a re-reference, a cast, or a decay has the referent of *r*, and a load through *r* with no field selection loads that referent. (rf(*d*) = rf(*r*) for a re-reference, cast, or decay *d* of *r*)

An object holds the references stored into it. In an object of a reference type, a store leaves the reference that the stored value is or holds at that object, or an unchained reference where it has none there, and a transfer leaves an unchained reference. A store or a transfer made through no reference replaces what is held by each object of a reference type that is the object it names or a constituent object of it. One made through a chained reference replaces nothing: in each choice, it adds what it leaves to what is held by each object of a reference type that is the referent of that reference or a constituent object of it. (a store or a transfer made through no reference, *o* the object it names: hold′(*o*′) = {*v*′} for each *o*′ of a reference type that is *o* or a constituent object of *o*; one through a chained reference *r*: hold′(*o*′) = hold(*o*′) ∪ {*v*′} in each choice, for each *o*′ of a reference type that is rf(*r*) or a constituent object of it; *v*′ being the reference that the stored value of a store is or holds at *o*′, and an unchained reference for a store whose stored value has none there and for a transfer)

*b* is **derived** from *e* where *b* is made from *e* (a creation of a managed reference, with any modifiers, from an object expression that passes through *e*, or a cast or a decay between managed reference types), or from a reference derived from *e*, or is a reference that an invocation derives from *e* (§8.1.2) or from a reference derived from *e*. *b* may be derived from *e* where it is derived from *e* in some choice. A decay, which takes place wherever this specification relates a type to another by assignability (§6.8), creates a reference, as the cast to that type does. A reference stored into an object of an unmanaged reference type decays so, and the object holds the reference the decay creates. Where *b* or *e* is an unmanaged reference, *b* is not derived from *e*.

For the chain rules, the stores into an object in a choice are the following:

&mdash; Each store, transfer, or invocation (§8.1.2) that may leave a reference in it in that choice. (a store, transfer, or invocation that may leave a reference in *o* in the choice at hand is a store into *o*)

&mdash; Where the object is tethered, every invocation, every store or transfer that may leave a reference, in that choice, in an untethered object or in an object of a reference type within a tethered object, and every store through a reference made from `static` by an invocation or a load, or derived from one. (for teth(*o*): every invocation, every store or transfer that may leave a reference in the choice at hand in an *o*′ with untethered(*o*′) or of a reference type within a tethered object, and every store through an *r* made from `static` by an invocation or a load or derived from such an *r*)

In each choice, a mortal object of the frame, a constituent object of one, or a tethered object **keeps**, at each point, one of the references it holds there (kept(*o*, *t*) ∈ hold(*o*) at *t*):

&mdash; At the start of the frame, any one.

&mdash; After a store or a transfer into it made through no reference, the one it left. (kept(*o*, *t*′) = *v*′, *t*′ the point after it and *v*′ what it left in *o*)

&mdash; After a store or a transfer into it made through a chained reference, the one it left or the one it kept before. (kept(*o*, *t*′) ∈ {*v*′, kept(*o*, *t*)}, *t* the point before it, *t*′ the point after it, and *v*′ what it left in *o*)

&mdash; After any other store into it, any one.

&mdash; With no store into it since the previous point, the one it kept there. (kept(*o*, *t*′) = kept(*o*, *t*) where no store into *o* lies between *t* and *t*′)

A load made through no unmanaged reference yields, from a mortal object of the frame, a constituent object of one, or a tethered object, the reference that object keeps in the choice at hand. From an immortal object, it yields a reference that it makes from `static`. From an untethered object, it yields one of the references that a load of an untethered object may yield, chosen independently of every other load. Any other load yields an unchained reference. (for a load ld at *t* made through no unmanaged reference, *o* the object it loads in the choice at hand: yield(ld) = kept(*o*, *t*) for *o* a mortal object of the frame, a constituent object of one, or a tethered object; yield(ld) is a reference ld makes from `static` for *o* an immortal object; for untethered(*o*), yield(ld) is one of those above, chosen independently of every other load; yield(ld) ∈ *Z* for any other load)

A tethered object holds, before any store, the reference at each position at which it was first reached. (hold<sub>0</sub>(*o*) = {the reference at *q* | *q* a position at which *o* was first reached})

A managed reference that carries `mut` is a **writing** reference.

A **store-kind access** is a store, a transfer (a load of an uncopyable value, which is also an access to its source), a write, or a derivation of a writing reference (a cast or decay to one included).

A **use** of a reference is its occurrence as the base of an access, of a derivation, of a cast, or of a decay, as a stored value, as an argument, as a reference at a position of an invocation, as a returned value, or as a copied or transferred value. The end of a body uses the result, every reference at a position of it whose possible referents include no untethered object, and every chained reference that the frame leaks. (end(*B*) uses ret(*B*) ∪ {*e* at a position of *B* | des(*e*) contains no untethered object} ∪ {*v* ∉ *Z* | leaked(*v*)})

A reference *e* is **pending** at *t* when born(*e*) &lt; *t* ≤ last(*e*). Uses are counted in the choice at hand: a use of a loaded value is a use of the reference that load yielded in that choice, and of no other reference the object holds; whether a reference may be derived from *e* is judged over every choice. A reference *e* with no use of *e* or of a reference that may be derived from *e* is never pending. (no such use ⇒ ¬pending(*e*, *t*) for every *t*)

#### Constraints

Each constraint of the chain rules shall be met on every trace. (for every trace, each constraint of the chain rules holds on it)

A store-kind access on objects that may overlap a possible referent of a pending exclusive reference *e* shall be made through *e* or through a reference derived from *e*. (skacc(*t*, *b*, *O*) ∧ excl(*e*) ∧ born(*e*) &lt; *t* ≤ last(*e*) ∧ des(*e*) ⋒ *O* ⇒ *b* ⊑ *e*, *b* being none for an access made through no reference, and skacc(*t*, *b*, *O*) a store-kind access at *t* through *b* on the objects *O*)

No exclusive reference shall be made, through no reference, from an immortal object. (excl(*d*) ∧ *d* made through no reference from *P* ⇒ *P* is no immortal object)

#### Design rationale (informative)

The constraints above are stated over what is pending because each trace of each frame determines it, and translation decides the chain rules.

#### Examples (informative)

```
fn id(r: $si4) -> $si4 { return r; }

struct holder {
    val: &si4
}

impl holder {
    fn get(&self) -> &si4 { return self.val; }
}

let mut x: si4 = 1;
let e: $mut si4 = $mut x;
let r = id($*e); // derived from the argument
// *e = 2;       // translation failure: r is pending
let v = *r;

let mut y: si4 = 2;
let g: $mut si4 = $mut y;
let h = holder.{ .val = &*g };
let s = h.get(); // derived from &h or from the reference h.val holds
*g = 3;          // s is shared: the store through g is permitted
let u = *s;      // 3
```

### 8.1.2 Routes

#### Syntax

```
routes_clause = "routes", ws, '(', ws, route, ws,
                { ',', ws, route, ws }, [ ',', ws ], ')' ;

route         = route_source, { ws, '+', ws, route_source }, ws,
                '->', ws, route_target ;
route_source  = "static" | route_path ;
route_target  = "return" | "static" | route_path ;
route_path    = { '*', ws }, [ '...', ws ],
                ( identifier | "self" | dec_literal ) ;
```

The `dec_literal` production is defined in §3.5.1.

#### Static semantics

Each `route` in a `routes` clause is a **route** of the declaration or type that carries it; its `route_source`s are its sources, and its `route_target` is its target.

A `route_path` that carries *k* `*` denotes layer *k* of a parameter and, where it carries `...`, each layer of that parameter deeper than layer *k*. (⟦*π*⟧ = {(*n*, *k*)} where *π* carries no `...`, and ⟦*π*⟧ = {(*n*, *j*) | *j* ≥ *k*} where it does, ⟦*π*⟧ the layers *π* denotes, *n* the index of the parameter the next sentence gives) The parameter is the one its identifier names, the self parameter where it carries `self`, or the one whose index is the digit value (§3.5.1) of its `dec_literal`, counting from zero in declaration order (§2.2.6), the self parameter included. (*n* = the digit value of the `dec_literal`, indices being 0, 1, … in declaration order with the self parameter included; for an identifier or `self`, *n* is the index of the parameter it names) `static` denotes no layer. (⟦`static`⟧ = ∅)

A subroutine declaration or subroutine pointer type that carries no `routes` clause has one route, whose target is `return` and whose sources denote every layer of every parameter and include `static`. (its one route has target `return` and sources *π* with ⋃ ⟦*π*⟧ = {(*n*, *k*) | *n* a parameter index, *k* ≥ 0}, `static` among them)

A subroutine declaration or subroutine pointer type **routes** each layer that a source of one of its routes denotes, and `static` where it is such a source, to the target of that route and to each layer that target denotes. (*λ* ↦<sub>*h*</sub> *μ* ⇔ for some route of *h* with target *π*′, (*λ* ∈ ⟦*π*⟧ for a source *π*, or *λ* = `static` and `static` is a source) ∧ (*μ* = *π*′ ∨ *μ* ∈ ⟦*π*′⟧))

Two subroutine declarations or subroutine pointer types have the **same routes** where, for `return`, for `static`, and for each layer of each parameter, the one routes to it the same layers, identified by parameter index and depth, as the other, and both or neither route `static` to it. (*λ* ↦<sub>*h*<sub>1</sub></sub> *μ* ⇔ *λ* ↦<sub>*h*<sub>2</sub></sub> *μ*, for every *λ* that is a layer or `static` and every *μ* that is `return`, `static`, or a layer)

In every signature, including that of an evaluation root, `static` is routed to `static`. (for ↦ and for each ↦<sub>*h*</sub> alike: `static` ↦ `static`)

A **position** of a subroutine is the object of one of its fixed parameters, or an object of a reference type reached from one by selections of constituent objects and by loads through managed references, along a path that reaches no immortal object. The positions of a body are those of its subroutine at the start of the frame. The positions at an invocation are those positions of the subroutine invoked that, once its arguments are evaluated and before the invocation leaves any reference, hold no unchained reference and are reached through none.

The object of a fixed parameter, and each constituent object of it, are **layer**-0 objects, and the references they hold are layer-0 references. The objects a layer-*k* reference designates, and each constituent object of them, are layer-(*k*+1) objects, and the references they hold are layer-(*k*+1) references.

The **stem** of a chained reference is given by the one of the following that describes it:

&mdash; Made by the frame from an object expression that reaches its object through a reference: the stem of the reference nearest the object (§6.4.3).

&mdash; Made by a cast or a decay from a reference *s*, or derived by an invocation from *s*: the stem of *s*.

&mdash; Made by the frame, through no reference, from a known object: the stem of that object.

&mdash; Made by an invocation or a load from `static`: `static`.

&mdash; At a position of the body that is first reached as a layer-*k* object of a parameter `p`: `p.k`.

An unchained reference has no stem.

The stem of a mortal object of the frame, or of a constituent object of one, is `local`, and that of an immortal object is `static`. Any other object has, as an access reaches it, one stem for each reference through which the access reaches it: the stem of that reference, one layer down. `p.k` becomes `p.k+1`, and `local` and `static` are unchanged. (stem(*o*) = `local` for *o* a mortal object of the frame or a constituent object of one, stem(*o*) = `static` for *o* an immortal object, and otherwise, for each *r* through which an access reaches *o*, the stem of *o* through *r* is shift(stem(*r*)), with shift(`local`) = `local`, shift(`static`) = `static`, and shift(`p.k`) = `p.k+1`)

An invocation is a use of every reference at its positions and of a shared reference it makes from `static`, and a store through each of these references into each possible referent of that reference and each constituent object of one. (for an invocation at *t*, each *r* ∈ {ref(*q*) | *q* a position at it} ∪ {*z*<sub>*t*</sub>} is used at *t*, and is the base of a store at *t* into des(*r*) and the constituent objects of its members, *z*<sub>*t*</sub> being a shared reference that the invocation makes from `static`)

In each choice, an invocation reaches objects from its arguments, each at a layer of a parameter and through a reference, as follows (in each choice, reach(*c*, *μ*) is the least set of pairs (*o*, *r*) with (rf(*r*), *r*) at (*n*, 1) for each *r* ∉ *Z* that the argument for parameter *n* is or holds, (rf(*r*′), *r*′) at (*n*, *k*+1) for each *r*′ ∉ *Z* that a load of *o* through *r* yields, (*o*, *r*) at (*n*, *k*), and (*o*′, *r*) at *μ* for each constituent object *o*′ of *o*, (*o*, *r*) at *μ*, *c* being the invocation and *μ* a layer of a parameter of the invoked subroutine):

&mdash; At layer 1 of a parameter, the referent of each chained reference that the argument for that parameter is or holds, through that chained reference.

&mdash; At layer *k*+1, the referent of each chained reference that a load of an object reached at layer *k* through a reference *r* yields through *r*, through the chained reference so yielded.

&mdash; At each layer, each constituent object of an object reached at that layer through a reference, through that same reference.

Afterwards, an object that the invocation reaches from its arguments holds its earlier reference or one that the invocation leaves in it: an unchained reference, a reference that the invocation derives from a reference at a layer routed to a layer at which that object is so reached, or, where `static` is routed to such a layer, a reference that the invocation makes from `static`. (hold′(*o*) ⊆ hold(*o*) ∪ {an unchained reference} ∪ {*d*<sub>*o*,*s*</sub> | *d*<sub>*o*,*s*</sub> derived by the invocation from an *s* at a layer *λ*, *λ* ↦<sub>*h*</sub> *μ*, (*o*, *r*) ∈ reach(*c*, *μ*) for an *r*} ∪ {*w* | *w* made from `static` by the invocation, `static` ↦<sub>*h*</sub> *μ*, (*o*, *r*) ∈ reach(*c*, *μ*) for an *r*}, for each *o* in a pair of a reach(*c*, *μ*))

The result is an unchained reference, a reference that the invocation derives from a reference at a layer routed to `return`, or, where `static` is routed to `return`, a reference it makes from `static`. (result ∈ {an unchained reference} ∪ {*d*<sub>ret,*s*</sub> | *d*<sub>ret,*s*</sub> derived by the invocation from an *s* at *λ*, *λ* ↦<sub>*h*</sub> `return`} ∪ {*d*<sub>ret,`static`</sub> | *d*<sub>ret,`static`</sub> made from `static` by the invocation, `static` ↦<sub>*h*</sub> `return`})

Each source gives each object that the invocation reaches from its arguments, and the result, a reference of its own. (each *d*<sub>*o*,*s*</sub>, *d*<sub>ret,*s*</sub>, and *d*<sub>ret,`static`</sub> is distinct, one per object or result and per source)

An invocation leaves, in an immortal object, a reference it derives from each reference at a layer that the signature of the invoked subroutine routes to `static`. (an invocation of *h* leaves, in an *o* that is an immortal object, a *d*<sub>*s*</sub> that it derives from each *s* at a layer *λ* with *λ* ↦<sub>*h*</sub> `static`)

A frame **leaves** a reference in an object by an invocation that leaves it there, and by its own store, made through no reference or through a chained reference, in each object that store accesses in some choice. (left(*v*, *o*) where an invocation of the frame leaves *v* in *o*, and where a store of *v* by the frame, made through no reference or through a chained reference, accesses *o* in some choice) The frame **leaks** each reference that it leaves in an immortal object or an untethered object. (leaked(*v*) ⇔ left(*v*, *o*) for an *o* that is an immortal object or an untethered object)

#### Constraints

At an invocation, the exclusive references at two distinct positions shall not have possible referents that may overlap. (*p* ≠ *q* ∧ excl(ref(*p*)) ∧ excl(ref(*q*)) ⇒ ¬(des(ref(*p*)) ⋒ des(ref(*q*))), *p*, *q* positions at the invocation)

A chained reference that a store of the frame leaves in an object shall have a stem that the frame’s own signature routes to each stem `static` or `p.k` that the object has as that store reaches it. (a store by the frame leaves a *v* ∉ *Z* in *o* ⇒ stem(*v*) ↦ *κ* for each stem *κ* ≠ `local` of *o* as that store reaches it) Where the subroutine that an invocation invokes routes *λ*, a layer or `static`, to `static`, each chained reference that the invocation derives from a reference at *λ*, and, where *λ* is `static`, each that it makes from `static`, shall have a stem that the frame’s own signature routes to `static`. Where it routes *λ* to a layer *μ*, each such reference shall have a stem that the frame’s own signature routes to each stem `static` or `p.k` that an object has as the invocation reaches it from its arguments at *μ*. (*λ* ↦<sub>*h*</sub> *μ* ∧ *μ* ≠ `return` ∧ *v* ∉ *Z* derived by the invocation *c* from an *s* at *λ*, or made by it from `static` with *λ* = `static` ⇒ stem(*v*) ↦ `static` for *μ* = `static`, and otherwise stem(*v*) ↦ *κ* for each (*o*, *r*) ∈ reach(*c*, *μ*) and each stem *κ* ≠ `local` that *o* has as *c* reaches it through *r*) A chained reference that the frame returns shall have a stem that the frame’s own signature routes to `return`. (return(*v*) ∧ *v* ∉ *Z* ⇒ stem(*v*) ↦ `return`)

A `route_path` shall denote a layer of a parameter of the declaration or type that carries it. (the *n* of ⟦*π*⟧ is the index of a parameter of the declaration or type that carries *π*) The target of a route shall be `return`, `static`, or a `route_path` that carries a `*`. (*π*′ ∈ {`return`, `static`} ∨ ⟦*π*′⟧ ⊆ {(*n*, *k*) | *k* ≥ 1}, *π*′ the target)

#### Examples (informative)

```
struct slot {
    h: &[ui1]
}

fn set(s: $mut slot, x: &[ui1]) routes(x -> *s) {
    s.h = x;
}

// fn put(s: $mut slot, x: &[ui1]) { s.h = x; }
// translation failure: no route to *s

struct words {
    s: &[&[ui1]],
    n: uaddr
}

impl words {
    fn next($mut self) -> &[ui1] routes(**...self + static -> return) {
        if self.n == 0 { return ""; }
        self.n -= 1;
        return *self.s.at(self.n);
    }
}

enum link {
    end,
    more { &mut node }
} with copyable;

struct node {
    val: si4,
    rest: link
}

impl node {
    fn append(&mut self, n: &mut node) routes(n -> *...self) {
        let mut cur: &mut node = self;
        airside {
            while let link::more.{ r } = cur.rest { cur = r; }
            cur.rest = link::more.{ n };
        }
    }
}

// With routes(n -> *self) instead on append,
// translation failure: cur may be at every layer of self

let mut sl = slot.{ .h = "" };
{
    let t: [ui1; 2] = [1, 2];
    // set($mut sl, &t); // translation failure: sl outlives t
}

let f: fn($mut slot, &[ui1]) routes(1 -> *0) = set;
// let p: fn($mut slot, &[ui1]) = set;
// translation failure: routes differ

let mut it = words.{ .s = &list, .n = list.len };
let a = it.next(); // from a literal in list, or made from static
let b = it.next(); // a is not derived from $mut it
print(a);
print(b);
```

### 8.1.3 Modifier placement

#### Static semantics

Two reference types that differ only in the order in which their modifiers are written are the same type.

#### Constraints

A reference type that repeats a modifier shall not appear.

### 8.2.2 Reference representation

#### Static semantics

A slice reference, or a reference to a protocol type, is a **wide reference**. It carries an address together with the **further information** needed to describe the referent. For a slice reference that information is the length. For a reference to a protocol type it is the pair of descriptor references that §9.6 defines. The referent of a reference to a protocol type is the object of its **erased type**, the type whose type descriptor `.tyd` designates, at the address `.ptr` carries.

#### Constraints

An expression that has the referent type of a wide reference shall be the operand of a reference creation.

### 8.2.3 Reference casting

Casts between reference types are written with `as`. A **re-reference** `tribe [modifiers] *expr`, where `expr` has a reference type, converts the reference that `expr` yields to a reference with the specified tribe and modifiers, and performs no access.

#### Static semantics

A cast between reference types or a re-reference requires airside where its tribe conversion or any of its modifier conversions requires airside.

A reference decays to each other reference type that has the same referent type and to which a cast from it is permitted and requires no airside. The decay yields the result of that cast.

#### Dynamic semantics

The result of a cast between reference types, and that of a re-reference, has the address and the further information of the reference it converts.

#### Constraints

A cast or a re-reference whose tribe conversion, or any of whose modifier conversions, is not permitted shall not appear.

Where the target type of a cast is a managed reference type, its referent type shall be the referent type of the source.

The source and the target of a cast between reference types shall both be slice references, both be references to a protocol type, or both be neither. Where both are references to a protocol type, their referent types shall be the same.

#### Design rationale (informative)

Atomicity (§2.1) belongs to each access, so adding or removing it changes only the accesses performed through the resulting reference. Removing it requires airside, so that the source text shows where an access can observe, or leave, a value written in part.

A cast from a managed reference to a form without `volatile` would permit the implementation to transform accesses this specification requires it to perform.

The store permission conversion permits no cast to `mut` from a managed reference without `mut`. Such a cast would confer store permission on an object whose binding withholds it.

```
// Tribe casts permitted on landside

let excl: $T = airside { express uman as $T; };    // %T → $T

// Prohibited tribe casts
// shared as $T; // translation failure: &T → $T

// Modifier casts

// &T → &volatile T
let vol: &volatile T = shared as &volatile T;
// &T → &atomic T
let atomic_view: &atomic T = shared as &atomic T;

let atomic_store: &atomic mut T = mut_ref as &atomic mut T;
// &atomic mut T → &atomic T
let load_only: &atomic T = atomic_store as &atomic T;
// &atomic mut T → &mut T, requiring airside
let plain: &mut T = airside { express atomic_store as &mut T; };

// translation failures:
// vol as &T;              // &volatile T → &T
// shared as &mut T;       // &T → &mut T

}
```

### 8.2.4 Conversion between a reference and `uaddr`

#### Static semantics

A reference and a `uaddr` are converted into one another with `as`. Neither the tribe conversion nor any modifier conversion applies to such a cast.

A cast from a reference to `uaddr` yields the address the reference carries.

#### Constraints

The source of a cast to a managed reference type shall be a reference type. A cast from `uaddr` to a wide reference shall not appear.

#### Implementation defined

What a cast from `uaddr` to an unmanaged reference type gives the reference besides the address is implementation defined.

#### Examples (informative)

```
let addr: uaddr = uman as uaddr;        // %T → uaddr: no reference
let direct: uaddr = exclusive as uaddr; // $T → uaddr
let uman2: %T = addr as %T;             // uaddr → %T

// addr as &T; // translation failure: uaddr casts to %T alone
```

### 8.2.5 Slice references

A **slice reference** describes a contiguous run of elements of the type its brackets enclose, whose count is determined at execution time.

#### Syntax

```
slice_reference = ref_tribe, ws, { ref_modifier, ws },
                  '[', ws, type, ws, ']' ;
```

#### Static semantics

The referent type of a slice reference is the array type of its element type (§4.10) whose length is the length the reference carries. In semantic analysis, the referent type of a slice reference is the same as that of each slice reference with the same element type, and as no other type. The values of the referent type of a slice reference are the values of the array types of its element type, of every length. A reference whose referent type is that of a slice reference is a slice reference with the same element type.

A reference to the array `[T; N]` decays to the corresponding slice reference. That is the slice reference whose tribe, modifiers, and element type match, whose `.ptr` carries the address of the array, and whose `.len` is `N`.

A `[T; N]` value and a slice reference both expose a reference to the first element and the length as built-in fields:

<table>
<thead><tr><th>Field</th><th>Type</th><th>Content</th></tr></thead>
<tbody>
<tr><td><code>ptr</code></td><td>as below</td><td>An unmanaged reference to the first element.</td></tr>
<tr><td><code>len</code></td><td><code>uaddr</code></td><td>The length.</td></tr>
</tbody>
</table>

When `.ptr` or `.len` is applied to an array value, the field expression is a **projection**. `.ptr` is then the address of the first element, and its projection creates a reference to that element; `.len` is `N`.

A slice reference has the stored representation defined below, and `.ptr` and `.len` of a slice reference object are the fields of that representation. Those of an unmanaged slice reference have field mutability.

The stored representation of a slice reference is two fields in this order:

<table>
<thead><tr><th>Field</th><th>Content</th></tr></thead>
<tbody>
<tr><td><code>ptr</code></td><td>unmanaged reference (reference width)</td></tr>
<tr><td><code>len</code></td><td><code>uaddr</code> (address width)</td></tr>
</tbody>
</table>

Kurt standard alignment gives the size and the alignment of the reference, and the offset of each field, from the types of those fields in that order.

The type of `.ptr` is an unmanaged reference. Where `.ptr` is a field of a slice reference, the modifiers `volatile`, `atomic`, and `mut`, where present on that reference, are inherited.

For a projection, `.ptr` carries `volatile` and `atomic` where an access to the array through the receiver (§6.3.2) of the projection is performed through a reference that carries them, and `mut` where a store to the array through the receiver of the projection is permitted at the programme point of the projection.

#### Constraints

A store through an object expression that designates a field of a managed wide reference, and the creation through such an object expression of a reference that permits stores, shall not appear.

#### Design rationale (informative)

The fields of an unmanaged slice reference have field mutability because constructing a slice reference from an arbitrary address and length requires stores to `.ptr` and `.len`. A store through a field of a managed wide reference would change what the reference designates without a derivation. A managed slice reference over an arbitrary address and length is therefore made from an unmanaged one by a cast, which requires airside, and is unchained.

`.ptr` has the unmanaged tribe because unmanaged reference arithmetic advances `.ptr` to neighbouring elements. Retaining a managed tribe would make every load of `.ptr` a derivation; retaining the exclusive tribe would issue mutually underived exclusive references to the same referent. The modifiers `volatile`, `atomic`, and `mut` are inherited because they apply to each access to the elements.

#### Examples (informative)

```
let arr: [si4; 3] = [10, 20, 30];
arr.ptr;              // %si4: address of first element
arr.len;              // 3
// arr.ptr = ...;     // translation failure: a projection is a value

let r: &[si4] = &arr; // &[si4; 3] decays to &[si4]
r.ptr;                // OK: load always permitted

let mut s: &[si4] = &arr;
// s.len = 2~uaddr;   // translation failure: s is a managed
                      // slice reference

// A managed slice reference over any address and length: cast
// an unmanaged one in airside; the result is unchained
let mut u: %[si4] = %arr;          // %[si4; 3] decays to %[si4]
u.ptr = 0x4000_1000~uaddr as %si4; // OK: u is unmanaged
u.len = 2~uaddr;
let m: &[si4] = airside { express u as &[si4]; };
```

## 8.3 Lifetime propagation

### Static semantics

A chained reference whose possible referents (§8.1.1) include a mortal object of the frame, or a constituent object of one, carries the shortest of the object lifetimes of its possible referents that are mortal objects of the frame or constituent objects of one. Every other managed reference carries the object lifetime of an immortal object (§2.2.6). (life(*r*) = min{life(*o*) | *o* ∈ des(*r*), *o* a mortal object of the frame or a constituent object of one} where *r* is chained and that set is not empty; life(*r*) = that of an immortal object otherwise)

The object lifetime a value of any other type carries is the shortest of those carried by the values it holds (§8.7). A value holding no value with an object lifetime carries none.

### Constraints

Using a binding after the object lifetime of its object has ended shall not appear. Such a violation, where not detected during translation, can cause indeterminate state.

A chained reference stored into an object whose object lifetime is longer than the object lifetime the reference carries shall not appear. A subroutine that returns a managed reference to an object whose object lifetime ends when the subroutine returns shall not appear. Either violation, where not detected during translation, can cause indeterminate state.

### Examples (informative)

```
// Single reference parameter: the result carries what data carries
fn passthrough(data: &[ui1]) -> &[ui1] {
    return data;
}

// Self parameter: the result carries the shortest of self and key
impl table {
    fn find(&self, key: &[ui1]) -> &[ui1] { ... }
}

// No parameter: the result carries the object lifetime of an
// immortal object
fn greeting() -> &[ui1] {
    return "hello";
}

// Struct: the instance carries the shortest object lifetime
// its fields carry
struct view {
    header: &[ui1],
    body: &[ui1]
}
```

## 8.4 Atomic references

### 8.4.1 Permitted operations

#### Static semantics

A reference carrying `atomic` is an **atomic reference**. An atomic reference `r` permits the load `*r`. One carrying `mut` also permits the store `*r = v` and the compare-and-swap (§8.6).

#### Dynamic semantics

Where the atomicity set (§2.1) the evaluation takes holds a pair whose size is that of the referent type of an atomic reference and for whose alignment the address that reference carries is aligned, every access through that reference is atomic. Otherwise such an access can cause indeterminate state.

#### Constraints

&mdash; Where a reference type carries `atomic`, its referent type shall satisfy `atomic` where that reference type is not a slice reference, and so shall the element type of its referent type where that referent type is an array type.

&mdash; An access through an atomic reference shall be performed by one of the expressions the static semantics above permit.

&mdash; A store or a compare-and-swap through an atomic reference created from a field expression shall appear only where that field expression is storable.

#### Examples (informative)

```
struct counters {
    // mut: atomic store permitted
    mut hits: ui4,
    // not mut: atomic store through &self not permitted
    misses: ui4
}

impl counters {
    fn record_hit(&self, seen: ui4) {
        // OK: hits is mut; creating a store-permitting reference
        // to it through &self requires airside
        airside { &atomic mut self.hits >.< seen then seen + 1; }
    }

    fn record_miss(&self, seen: ui4) {
        // &atomic mut self.misses >.< seen then seen + 1;
        // translation failure: misses is not mut
    }

    fn read_misses(&self) -> ui4 {
        return *(&atomic self.misses); // OK: load, no mut required
    }
}
```

### 8.4.2 Ordering fences

The `volatile_fence` is the **translation ordering fence**, and the `guard_fence` is the **execution ordering fence**. These are the two **ordering fences**. Each `fence_word` of an ordering fence is one of its **fence words**.

#### Syntax

```
volatile_fence = "volatile", fence_form ;
guard_fence    = "guard",    fence_form ;
fence_form     = { ws, '.', ws, fence_word }, ws, '(', ws, ')' ;
fence_word     = 'r' | 'w' | 'l' | 's' | 'rl' | 'lr' | 'rs' | 'sr'
               | 'wl' | 'lw' | 'ws' | 'sw' ;
```

#### Static semantics

An ordering fence is an expression whose value is `void`.

The fence words name the ordering properties. `rl` and `lr` name the property that a fence relays loads, `rs` and `sr` that it relays stores, `wl` and `lw` that it withholds loads, and `ws` and `sw` that it withholds stores (§2.3.2). `r` names those of `rl` and `rs`, `w` those of `wl` and `ws`, `l` those of `rl` and `wl`, and `s` those of `rs` and `ws`. An ordering fence has the ordering properties its fence words name, and all four where it names none. (props(`rl`) = props(`lr`) = {relays loads}, props(`rs`) = props(`sr`) = {relays stores}, props(`wl`) = props(`lw`) = {withholds loads}, props(`ws`) = props(`sw`) = {withholds stores}; props(`r`) = props(`rl`) ∪ props(`rs`), props(`w`) = props(`wl`) ∪ props(`ws`), props(`l`) = props(`rl`) ∪ props(`wl`), props(`s`) = props(`rs`) ∪ props(`ws`); props(*F*) = ⋃ props(*x*) over the fence words *x* of an ordering fence *F*, and all four properties where *F* has none)

#### Dynamic semantics

The effect of an execution ordering fence is the union of the effects of its components, as §2.3.2 defines them.

#### Implementation requirements

For each ordering property of a translation ordering fence, with the kind pair (*k*<sub>1</sub>, *k*<sub>2</sub>), the implementation shall not perform a τ operation (§2.2.1) of an evaluation of kind *k*<sub>2</sub> that is later than the fence in the programme order of its execution context (§2.1) before it performs a τ operation of an evaluation of kind *k*<sub>1</sub> that is earlier than the fence in that order.

#### Examples (informative)

```
// `.rl()` follows the load it orders, `.rs()` precedes the store
// it orders. flag, ready, data and result are `static mut`
// objects, and the code of each execution context lies within an
// airside region.

// translation ordering fence: fence words rl and rs
// (one execution context)
let seen = *&atomic flag;
volatile.rl();
volatile.rs();
*&atomic mut flag = 1;

// translation ordering fence: no fence word
// (one execution context)
volatile();
*&atomic mut ready = 1;

// execution ordering fence: fence words rl and rs
// (several execution contexts)
let val = *&atomic data;
guard.rl();
// ... use val ...
guard.rs();
*&atomic mut result = computed;

// execution ordering fence: no fence word
// (several execution contexts)
guard();
```

## 8.5 Unmanaged reference arithmetic

### Static semantics

Where the synthesized type of the leading operand of `+` or `-` is an unmanaged reference type, the result type is the type of the leading operand.

### Dynamic semantics

The cell offset is the following operand multiplied by `T'size`, where `T` is the referent type, or the element type where the leading operand is a slice reference. The result carries the address that the leading operand carries, advanced by the offset for `+` and set back by it for `-`. Both the multiplication and the address computation follow the wrapping semantics defined in §6.5.1.

Where the leading operand is a wide reference, the result carries the same further information.

### Implementation requirements

The implementation should issue an advisory diagnostic (§2.8.1) where `T'size` is zero.

### Examples (informative)

```
let base: %si4 = arr.ptr;
let third: %si4 = base + 2; // 2 * si4'size cells forwards
let prev: %si4 = third - 1; // 1 * si4'size cells backwards

let mut cursor: %si4 = arr.ptr;
cursor += 1; // advance one element
cursor -= 1; // retreat one element

let vp: %volatile atomic mut ui4 = mmio_base;
let next_reg: %volatile atomic mut ui4 = vp + 1; // modifiers preserved

// Cell-level arithmetic: cast to %ui1
let cell_ptr: %ui1 = base as %ui1;
let offset: %ui1 = cell_ptr + 16; // 16 cells forwards
```

## 8.6 Compare-and-swap operator

### Syntax

```
cas_expr = expression, ws, '>.<', ws, expression, ws, "then", ws,
           expression ;
```

### Static semantics

The compare-and-swap operator has the result type `verdict[T, T]`, where `T` is the referent type of the target.

### Dynamic semantics

In `target >.< expected then new`, the three operands are evaluated in that order.

The operation performs a joint access through the target. Where the transactionality set (§2.1) the evaluation takes holds a pair whose size is that of the referent type and for whose alignment the address the target carries is aligned, its load part and its store part (§2.3.4) are transactional. Otherwise the operation can cause indeterminate state.

The storing condition (§2.3.4) of that joint access is that the value its load part observes is `expected`. Where that joint access succeeds, its store part stores `new` and the operation yields the success variant; otherwise the operation yields the failure variant. Either variant contains the value its load part observes. Where that joint access fails, it may perform a store of the value its load part observes.

### Constraints

The target shall be an atomic reference carrying `mut`, and `expected` and `new` shall be of its referent type. The referent type shall satisfy `transact` (§9.7.7).

### Implementation defined

The conditions under which the joint access fails where its load part observes `expected` are implementation defined.

Whether the joint access performs a store where it fails is implementation defined.

### Examples (informative)

```
// Unordered CAS with asymmetric fencing: `guard.rs()` precedes
// the operation, `guard.rl()` follows it. The `guard()` pair around
// the first load orders it with every access before and after it.
guard();
let mut expected = *&atomic ctr;
guard();
loop {
    guard.rs();
    match &atomic mut ctr >.< expected then new {
        let verdict::Pass.{ old }    -> { guard.rl(); break; };
        let verdict::Fail.{ actual } -> { expected = actual; };
    }
}

// CAS ordered with every access before and after it: a fence
// naming no fence word on each side
guard();
let result = &atomic mut ctr >.< expected then new;
guard();
if result -> old {
    // CAS succeeded
} else.actual {
    expected = actual;
}

// Replacement whenever the target holds any value other than a
// sentinel. Both sentinel and real_value are integer constants.
let slot_ref = &atomic mut slot;
loop {
    guard();
    let cur = *slot_ref;
    guard();
    if cur == sentinel { break; }
    match slot_ref >.< cur then real_value {
        let verdict::Pass.{ old } -> { guard(); process(old); break; };
        verdict::Fail             -> { };
    }
}
```

## 8.7 Copy and transfer semantics

A value of a struct type or of an anonymous struct type holds the value of each of its fields other than a `?` field, and a value of an array type the value of each of its elements. A value of a variant type (§4.6) holds its discriminant and the value of each field, other than a `?` field, of the variant it holds. A value held by a value that another value holds is held by that other value.

The **constituents** of a type are the types of the values a value of the type holds. The constituents of a variant type are its discriminant type and the types of the fields, other than `?` fields, of all its variants. A reference type has no constituents.

A built-in type or a composite type whose declaration carries `with copyable` is **copyable** where each of its constituents is copyable, unless this specification states it to be **uncopyable**. Any other composite type is uncopyable. A type with an uncopyable constituent is uncopyable. In semantic analysis, a type parameter (§4.10) is copyable where it satisfies `copyable`, and neither classification applies to it otherwise.

A reference whose value is used only to designate its referent, to create a reference from it, or as the operand of a cast or of a decay is neither copied nor transferred.

### Dynamic semantics

A **copy** of a value that a load yields performs, at each cell of the destination storage, a write of the symbol that load read at the corresponding cell of the storage region (§2.2.2) of the object it names.

A load, other than through an unmanaged reference, of a value of an uncopyable type **transfers** that value where it yields it, and any other load yields a value to be copied.

A matching **takes** each portion bound by a binding that receives a value from that matching. It also takes each payload that the subclause defining its construct states to be, or to be held by, the value of the construct or a value the enclosing subroutine returns. A load that a matching performs yields the value of each portion that the matching takes, and yields no other value. To each value so yielded, the definitions of a copy and of a transfer in this subclause apply as to a load of that portion through the reference, if any, through which that load is performed.

The object that a transferring load names is the source of that transfer. The transfer invalidates its source. Then, where the outermost object (§2.2.4) of the source is still initialized, the value that outermost object holds is destroyed, as §8.8.1 defines, and the outermost object is invalidated. The transfers of one matching invalidate all their sources before any such destruction.

### Constraints

The type of each field of a declaration that carries `with copyable` shall be copyable where the type argument (§4.10) for each type parameter of the declaration is copyable.

On each trace, from the invalidation of the outermost object of the source of a transfer up to and including the next store made through no reference into that outermost object, the following apply to that outermost object at each access other than through an unmanaged reference and at each creation of a managed reference:

&mdash; Neither it nor any constituent object of it shall be loaded or have a managed reference to it created.

&mdash; No constituent object of it shall be stored into.

Such a violation through a reference, where not detected during translation, can cause indeterminate state.

The sources of the transfers of one matching shall be distinct objects, none of which is a constituent object of another.

No source of a transfer shall be an immortal object, or a constituent object of an object of a type whose destructor is a `with destruct` block or one the implementation supplies.

A load through a managed reference shall transfer no value. Where such a load yields a reference of an uncopyable type and that reference is used to store through it or to create a reference that permits stores, the object expression that yields it shall be storable.

### Examples (informative)

```
// managed, copyable: copy
let r: &si4 = &x;
let v = *r; // copy

// managed, uncopyable store: transfer; the existing value
// is destroyed before the write
*$mut handle_ref = open("c.bin");

// unmanaged: a load copies, a store destroys nothing
airside {
    let val = *(%*src);      // copy, destroyed independently
    *(%mut dst) = new_value; // existing value not destroyed
}

// swap via unmanaged references
pub airside fn swap[T](a: $mut T, b: $mut T)
    routes(*b -> *a, *a -> *b) {
    let mut tmp: T = unwritten;
    *(%mut tmp) = *(%*a);
    *(%mut *a)  = *(%*b);
    *(%mut *b)  = *(%tmp);
    undrop(tmp);
}
```

## 8.8 Destructors

### Syntax

```
destruct_clause = 'destruct', ws, block ;
```

### Static semantics

Every type has a **destructor**: the block of the `with destruct` clause where its declaration carries one, the subroutine the implementation supplies for the type where this specification states that it supplies one, and otherwise its **default destructor**, a subroutine with no operation.

Within a `with destruct` block, `self` is an exclusive reference to the object being destroyed, and carries `mut`. The block is the body of a subroutine with return type `void` and no `routes` clause, whose one declared parameter is a self parameter that the word `destruct` introduces into the block. Its invocation also receives the type descriptor of the type, as the subroutine that field 2 of that descriptor designates receives it, as §9.5 defines.

### Dynamic semantics

No value is destroyed other than as a rule of this specification calls for.

### Examples (informative)

```
// x is destroyed where the body ends
fn drop[T](x: T) {}

// A store through an unmanaged reference destroys nothing and
// leaves sink uninitialized: x, where its type is uncopyable,
// is transferred to it, and neither is destroyed where the body
// ends
airside fn undrop[T](x: T) {
    let mut sink: T;
    *(%mut sink) = x;
}

{
    let handle = open_file("data.bin");
    process(&handle);
    drop(handle); // destructor is invoked here, not at scope exit
    do_unrelated_work();
}

airside { undrop(existing_handle); }
// existing_handle is invalidated. The destructor is not invoked.
```

### 8.8.1 Composite destruction

#### Dynamic semantics

Destroying the value an object holds invokes the destructor of its type. It then destroys, in this order, the value held by each initialized constituent object that its type places directly and that the definition of holding names for that value:

&mdash; Struct or variant type &mdash; the values the fields hold are destroyed in reverse declaration order, and then, for a variant type, the value its discriminant holds.

&mdash; Anonymous struct type &mdash; the values the fields hold are destroyed in reverse index order.

&mdash; Array type &mdash; the value each element holds is destroyed in reverse index order.

#### Examples (informative)

```
struct buffer {
    data: %ui1,
    len: uaddr
} with destruct {
    // self: $mut buffer
    release(self.data, self.len);
};

struct parser {
    buf: buffer,
    pos: uaddr
}

let p1 = parser.{ .buf = alloc_buffer(1024), .pos = 0 };
let p2 = p1; // transfer: p1 is invalidated
// p1.pos;   // translation failure: p1 was transferred

// When p2 goes out of scope:
//   1. destroying p2.pos performs no operation
//   2. destroying p2.buf invokes buffer’s destructor (release)

enum resource {
    file { file_handle },
    none
}
// Destroying a resource value destroys the fields of the variant
// the discriminant matches, and then the discriminant: file
// destroys its field first, none only the discriminant.
```
