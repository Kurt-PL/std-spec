# 9. Protocols and implementations

This clause defines implementations and protocols: inherent implementations, associated subroutines and associated constants, protocol declarations and implementations, descriptors, protocol types, and the built-in bounds.

## 9.1 Inherent implementations

An `impl` block introduces associated subroutines and associated constants for a type. An `impl` block without an `as` clause is an **inherent implementation**, and introduces them into the type’s own namespace. One with an `as` clause is a **protocol implementation**, defined in the subclause on protocol implementations. An `impl(...)` parameter list introduces generic parameters whose scope is the whole `impl` block, the target type and the `as` clause included.

### Syntax

```
impl_block = "impl", [ ws, impl_generic_params ], ws, type,
             [ ws, "as", ws, single_path ],
             ws, '{', ws, { impl_item, ws }, '}' ;

impl_generic_params = '(', ws, generic_item, ws,
                      { ',', ws, generic_item, ws }, [ ',', ws ],
                      ')' ;

impl_item = { item_prefix, ws },
            ( method_def | associated_const_def ) ;

associated_const_def = [ "pub", ws ], "const", ws, identifier, ws,
                       [ ':', ws, type, ws ], '=', ws, expression,
                       ';' ;
```

### Static semantics

An **associated constant** is a constant scoped to the type’s namespace. Its expression is the one the `impl` block gives, or the default expression of the protocol where the block gives none. Where no generic parameter occurs free in that expression, it is evaluated at translation time, once for each machine on which it would be analysed were it not an analysis root or for which a protocol descriptor with a field for it is emitted. Otherwise it is evaluated in each evaluation that names the associated constant and does not load it from a protocol descriptor, and once in the emission of each protocol descriptor with a field for it, on the machine of that descriptor.

For the visibility modifier, defined in the clause on declarations, the namespace that declares an item of an `impl` block is the one that encloses the block, and the namespace that declares a protocol item the one that encloses the `protocol` declaration.

A **parameter anchor** of a parameter of an `impl(...)` parameter list is the target type where the target type is the parameter itself. It is also each type argument or dependence argument, of the target type or of the protocol the `as` clause names and at any depth of nesting, that is the parameter itself. The bound of the parameter is the bound the list places upon it, followed by the bound elements that each generic declaration places on the generic parameter a parameter anchor of it resolves. The elements of each such declaration are taken with its arguments substituted and in its declaration order, and the parameter anchors in the order they appear in the target type and then in the `as` clause. An element already in the bound is not repeated.

An `impl` block is on a type where its target type is that type, or resolves to it under a resolution of the parameters of its `impl(...)` parameter list in which each argument satisfies the bound of the parameter it resolves.

### Constraints

Each parameter of an `impl(...)` parameter list shall have a parameter anchor. In a protocol implementation, the `impl(...)` parameter list shall place no bound upon a parameter.

### Examples (informative)

```
impl(T) stack[T] {
    // Associated subroutine: constructor, invoked via stack::new()
    pub fn new() -> selftype { ... }

    // Associated subroutine: factory with capacity
    pub fn with_capacity(cap: uaddr) -> selftype { ... }

    // Methods: invoked via value.method()
    pub fn push($self, val: T) routes(val -> *...self) { ... }
    pub fn pop($self) -> verdict[T, void] { ... }
    pub fn len(&self) -> uaddr { return self.len; }
    pub fn is_empty(&self) -> verdict[void, void] {
        return self.len == 0;
    }
}

impl si4 {
    // Associated constants: accessed via si4::min, si4::max
    pub const min: si4 = -2147483648;
    pub const max: si4 = 2147483647;
    // type inferred from the initializer
    pub const zero = 0~si4;
}

// Usage
let mut s = stack[si4]::new();  // associated subroutine
s.push(42);                     // method
let m = si4::max;               // associated constant
```

## 9.2 Associated subroutine declarations

### Syntax

```
method_def          = [ "pub", ws ], [ "airside", ws ], "fn", ws,
                      identifier, [ ws, generic_clause ], ws, '(', ws,
                      [ method_params, ws ], ')',
                      [ ws, subroutine_return ],
                      [ ws, routes_clause ],
                      [ ws, with_single | ws, with_curly ], ws, block ;

subroutine_proto    = [ "pub", ws ], [ "airside", ws ], "fn", ws,
                      identifier, [ ws, generic_clause ], ws, '(', ws,
                      [ subroutine_proto_params, ws ], ')',
                      [ ws, subroutine_return ],
                      [ ws, routes_clause ],
                      [ ws, with_single | ws, with_curly ], ws, ';' ;

method_params       = self_param, [ ws, ',', ws, [ parameter_list ] ]
                    | parameter_list ;

subroutine_proto_params = self_param,
                      [ ws, ',', ws, [ proto_parameter_list ] ]
                    | proto_parameter_list ;

self_param          = [ ( ( '&' | '$' ), ws,
                      { ref_modifier, ws } )
                      | ( "mut", ws ) ],
                      ( "self" | '[', ws, "self", ws, ']' ) ;
```

### Static semantics

A subroutine in an `impl` block or protocol body is an **associated subroutine**. It is invoked through a qualified path. An associated subroutine that carries a self parameter is a **method**, and is invoked through the `.` operator as well.

`selftype` is a keyword that stands, as the root of a path, for a type the enclosing declaration fixes as follows:

&mdash; An `impl` block &mdash; its target type, from the point where that type is written to the end of the block. Where the block carries an `as` clause, `selftype` is, for signature lowering alone, a type parameter of every subroutine the block provides, and the bound upon it there is the protocol the `as` clause names.

&mdash; A `protocol` declaration &mdash; the type of an eventual implementer, throughout the declaration. `selftype` is a type parameter of every item the protocol declares, preceding every type parameter the item declares, and the bound upon it is the protocol that declares the item.

&mdash; A `struct`, `enum`, or `contract` declaration &mdash; the type the declaration introduces, with its own generic parameters as the generic arguments. `selftype` takes generic arguments as the declaration’s name does, and then stands for the instantiation they give.

The self parameter forms are:

&mdash; `self` and `mut self` &mdash; the receiver by value. Equivalent respectively to `self: selftype` and to `mut self: selftype`.

&mdash; `X self` and `X[self]`, where `X` combines the tribe `&` or `$` with any permitted modifiers &mdash; equivalent respectively to `self: X selftype` and to `self: X[selftype]`, the latter a slice reference with element type `selftype`.

### Constraints

A `selftype` that carries generic arguments shall appear only within a `struct`, `enum`, or `contract` declaration.

A bracketed receiver shall carry a tribe.

### Design rationale (informative)

A slice appears only as the referent of a reference. The bracketed forms therefore require the `&` or `$` tribe.

`%` is excluded because permitting `%self` would conceal an access through an unmanaged reference behind `.` or impose a receiver-dependent `airside` requirement at the invocation site. A subroutine with no self parameter, taking `%selftype` as its leading parameter, provides the same operation through ordinary invocation syntax inside an `airside` block.

### Examples (informative)

```
impl(T) T {
    fn at(&[self], idx: uaddr) -> &selftype {
        // self: &[T]
        ...
    }

    fn at_xcl($[self], idx: uaddr) -> $selftype {
        // self: $[T]
        ...
    }
}
```

### 9.2.1 Name resolution

#### Static semantics

Where, in a method invocation `e.m(args)`, the type of `e` after reference transparency is a protocol type, that protocol is searched. A search of a protocol reaches the method named `m` that the protocol declares, and, where the protocol declares no method of that name, proceeds through the protocols its bound list names, in declaration order, each searched by this same rule. Where the searches for an invocation reach methods named `m` of exactly one protocol instantiation between them, the invocation resolves to the method named `m` of that instantiation, by the first path the searches take. Where they reach methods named `m` of two or more protocol instantiations, the invocation is ambiguous. Where they reach none, the invocation resolves to no method.

Where the search for a protocol type or for a type parameter reaches a method whose self parameter is bracketed, the invocation resolves to no method. Where the search for a protocol type reaches a method whose signature mentions `selftype` other than as the type of its self parameter, the invocation resolves to no method.

Where the type of `e` after reference transparency is a type parameter, each protocol its bound names is searched as the first paragraph of this subclause searches a protocol, in the order the bound names them, and the invocation resolves as that paragraph defines.

Where that type is `[U]` or `[U; N]`, and the procedure of the next paragraph applied to that type resolves to no method, the invocation resolves by that procedure applied to `U`, under which only a method whose self parameter is bracketed resolves. Under every other application of that procedure, only a method whose self parameter is not bracketed resolves.

For every other type, a method invocation `e.m(args)` is resolved by the following procedure, applied to that type:

1. If an inherent `impl` block on the type provides a method named `m`, the invocation resolves to the method.
2. Otherwise, the protocols of the implementations witnessed for the type, as the subclause on `with impl` defines witnessed implementations, are searched, each as the first paragraph of this subclause searches a protocol:

&mdash; Where the searches reach methods named `m` of exactly one implementation between them, the invocation resolves to the method named `m` of that implementation, by the first path the searches take.

&mdash; Where they reach methods named `m` of two or more implementations, the invocation is ambiguous.

&mdash; Where they reach none, the invocation resolves to no method.

A qualified method invocation `(e as Protocol).m(args)`, defined in the clause on expressions, is resolved as `e.m(args)` is, as if no inherent `impl` block provided, and no protocol other than `Protocol` declared, a method named `m`.

The same resolution procedure applies to associated subroutines and associated constants accessed through a path (`Type::item`), an associated item taking the place of a method. A path whose qualified path root is `(Type as Protocol)` reaches the item from the implementation of `Protocol` for `Type` that is witnessed, as the subclause on `with impl` defines witnessed implementations.

#### Constraints

An invocation or access that is ambiguous, or that resolves to no method or no associated item, shall not appear.

#### Examples (informative)

```
// Inherent method takes priority over protocol method
struct counter { val: ui4 }

impl counter {
    pub fn get(&self) -> ui4 { return self.val; }
}

protocol readable {
    fn get(&self) -> ui4;
}

impl counter as readable {
    fn get(&self) -> ui4 { return self.val * 2; }
}

let c = counter.{ .val = 5 };
c.get();          // resolves to inherent: yields 5
(c as readable).get(); // resolves to readable impl: yields 10

// Single protocol method, no inherent
struct widget;

impl widget as drawable {
    fn draw(&self) { ... }
}

let w = widget;
w.draw();         // resolves to drawable::draw

// Two protocol methods, no inherent
protocol render { fn draw(&self); }
protocol paint  { fn draw(&self); }

impl widget as render { fn draw(&self) { ... } }
impl widget as paint  { fn draw(&self) { ... } }

// w.draw();          // translation failure: ambiguous
(w as render).draw(); // OK
(w as paint).draw();  // OK
```

## 9.3 Protocol declarations

### Syntax

```
protocol_decl = [ "pub", ws ], "protocol", ws, identifier,
                [ ws, generic_clause ],
                [ ws, ':', ws, bound ],
                ws, '{', ws, { protocol_item, ws }, '}' ;

protocol_item = { item_prefix, ws },
                ( subroutine_proto | default_subroutine
                | associated_const ) ;

default_subroutine = method_def ;
associated_const = [ "pub", ws ], "const", ws, identifier, ws, ':',
                   ws, type, [ ws, '=', ws, expression ], ws, ';' ;
```

### Static semantics

A protocol body contains zero or more **protocol items**: subroutine prototypes, default protocol subroutines, and associated constants. A default protocol subroutine may name every other protocol item of the protocol.

#### Protocol identity

One protocol declaration is **congruent** with another where all of the following hold. In each item, corresponding generic parameters of the two declarations and corresponding generic parameters of the associated subroutines they declare are taken to be the same generic parameter, and the `selftype` of the one and that of the other to be the same type.

&mdash; The two declare the same number of generic parameters, and corresponding parameters, in declaration order, are of the same kind. Corresponding dependence parameters bear the same type. Corresponding type parameters bear the same number of bound elements, and their corresponding elements, in the order of the bound, agree as the next item defines agreement.

&mdash; The two declare the same number of bound elements, and corresponding elements agree, in declaration order. Two elements naming declared protocols agree where those declarations are congruent and their generic arguments are the same. Two elements naming built-in bounds agree where they name the same bound.

&mdash; The two declare the same number of associated subroutines. Corresponding subroutines, in declaration order, bear the same airside status, generic clauses whose parameters correspond as the first item requires, self parameters of the same type, the same parameter types in order, the same return type or `!`, the same routes, and the same number of subject bounds, corresponding subject bounds agreeing in order. Two subject bounds agree where their subjects are the same and their protocols agree as the second item defines agreement.

&mdash; The two declare the same number of associated constants, and corresponding constants bear the same type, in declaration order.

A descriptor emitted under one declaration describes every declaration congruent with it.

A descriptor reaches a translation unit other than the one that emitted it, as `#dyn` permits. Where the declaration the receiving unit reads is not congruent with the declaration the emitting unit reads, an access through the descriptor can cause indeterminate state.

### 9.3.1 Associated constants in protocols

#### Examples (informative)

```
pub protocol bounded: copyable {
    const min: selftype;
    const max: selftype;
}

impl ui1 as bounded {
    const min: ui1 = 0;
    const max: ui1 = 255;
}

fn clamp[T: bounded + primitive](val: T) -> T {
    let lo = (T as bounded)::min;
    let hi = (T as bounded)::max;
    return if val < lo then lo else if val > hi then hi else val;
}
```

### 9.3.2 The bound upon a protocol

#### Static semantics

A protocol **entails** each bound element its bound list names and each bound element that a protocol its bound list names entails. The protocol items of a protocol the bound list names may be named unqualified within the default protocol subroutines of the protocol.

#### Constraints

A protocol shall not entail a bound element that names it.

#### Examples (informative)

```
pub protocol printable: fmt + clone {
    fn print(&self) { let d: &dyn fmt = self; println("{}", &[d]); }
}
```

### 9.3.3 Default protocol subroutines

#### Static semantics

A **default protocol subroutine** is a protocol item whose declaration stands in the protocol body with its body present. Where an `impl` block for a type does not provide the item, that body is used. Where the `impl` block provides it, the provided body replaces the default entirely.

#### Examples (informative)

```
pub protocol encodable {
    fn name(&self) -> &[ui1];

    fn encode(&self, out: $[ui1]) -> verdict[uaddr, &[ui1]] {
        // invokes the subroutine prototype
        return verdict::Fail.{ self.name() };
    }
}
```

## 9.4 Protocol implementations

A protocol `impl` block provides the associated subroutines and associated constants for a protocol on a type.

### Constraints

Every subroutine prototype declared in the protocol shall be provided. An associated constant shall be provided unless the protocol provides a default expression for it. A protocol `impl` block shall provide only items the protocol declares.

An associated subroutine a protocol `impl` block provides shall state the following as the protocol declares them, in the same order:

&mdash; The airside status.

&mdash; The generic clause.

&mdash; The type of the self parameter.

&mdash; Each parameter type.

&mdash; The return type or `!`.

&mdash; The subject bounds.

In each of them, the generic arguments of the `as` clause are substituted for the protocol’s generic parameters, and the target type for `selftype`. The subroutine shall have the same routes as the protocol’s declaration of it. An associated constant a protocol `impl` block provides shall bear the type the protocol declares for it, with the same substitutions.

The implementing type shall satisfy each bound element that the bound list of the protocol names, with the generic arguments of the `as` clause substituted for the protocol’s generic parameters. Where the protocol `impl` block carries an `impl(...)` parameter list, it shall do so under each resolution of the parameters of that list in which each argument satisfies the bound of the parameter it resolves.

### Examples (informative)

```
impl si4 as ord {
    fn cmp(&self, other: &selftype) -> ordering {
        return if *self > *other then ordering::greater
        else if *self < *other then ordering::less
        else ordering::equal;
    }
}

impl vec[si4] as iterator[si4] {
    fn next($self) -> verdict[si4, void] {
        if self.pos < self.len {
            let val = *self.data.at(self.pos);
            self.pos += 1;
            return verdict::Pass.{ val };
        } else {
            return verdict::Fail.{ void };
        }
    }
}
```

### 9.4.1 Duplicate detection

#### Static semantics

A translation unit emits, for each machine, at most one protocol descriptor for each protocol instantiation that a type implements within it, and the zone 2 fields of each designate the bodies that unit reads.

#### Constraints

A type shall implement a given protocol instantiation at most once within the same translation unit. Instantiations that resolve the protocol’s generic parameters differently are distinct.

#### Implementation requirements

The diagnostic for two implementations of one protocol instantiation shall identify both and a source unit from which both are reached in the `#add` dependency graph.

### 9.4.2 `with impl`

A `with impl` item requires that a type implement a protocol, and makes that implementation witnessed within the subroutine that carries it.

#### Syntax

```
subject_bound = "impl", ws, type, ws, "as", ws, single_path ;
```

#### Static semantics

A `with impl` item is a **subject bound**. It stands in the `with` clause of a subroutine definition, of the definition of an associated subroutine, of a subroutine prototype, or of a subroutine pointer type. The type it names before `as` is its **subject**, and the protocol its `single_path` names is its protocol.

An implementation of a protocol for a type is reached within a construct only where it is **witnessed** within that construct, and a protocol descriptor is formed only for an implementation witnessed where it is formed. Where a rule names no construct, the construct is the one that rule governs. Where the type is a closed type and no generic parameter occurs free in a generic argument of the protocol, every implementation of the protocol for the type is witnessed everywhere. Otherwise, the implementations witnessed within a construct are the following.

&mdash; Where a type parameter is in scope, the implementations a bound upon it names for it.

&mdash; Within a subroutine declaration, the implementations its subject bounds name for their subjects.

&mdash; Within a protocol `impl` block, the implementation the block provides for its target type.

&mdash; For each implementation witnessed, the implementations for the same type of the protocols the bound list of its protocol names, with the generic arguments of its protocol substituted.

At each invocation of the subroutine, the argument to which each generic parameter of a subject bound resolves is substituted into that subject bound. For each subject bound so substituted, the invoker supplies an implementation of the protocol for the subject that is witnessed within the invoker.

#### Constraints

Except within the signature of an associated subroutine that a protocol `impl` block provides, each of the following shall hold of a subject bound:

&mdash; A generic parameter occurs free in its subject or in a generic argument of its protocol.

&mdash; Its subject is not a type parameter.

&mdash; No other subject bound of the same declaration bears the same subject and the same protocol instantiation.

`selftype` shall not occur free in the subject of a subject bound of an associated subroutine that a protocol body declares, or in a generic argument of its protocol.

An invocation whose invoker cannot supply a witnessed implementation for a subject bound, or for a bound element of a type parameter that names a declared protocol, shall not appear.

## 9.5 Descriptors

A **descriptor** is an object that the implementation emits for a type. The type of a reference to a descriptor is `%void`.

Each subclause below gives the fields of one kind of descriptor, in order. Kurt standard alignment, applied to that sequence of field types, gives the offset of each field and the size and the alignment of the descriptor. A descriptor belongs to a machine, as the clause on expressions defines. A field type whose width derives from the cell width takes the cell width of that machine.

A protocol item is reached through a descriptor in two stages. **Item resolution** takes a name to the item it denotes, within the declaration the translation unit reads, as the subclause on name resolution defines. **Selection** takes that item to the field it occupies, by the index its declaration order assigns it.

Field 2 designates a subroutine that destroys a value of the type, as the subclause on composite destruction defines destroying a value. It is invoked with the object to destroy as its first argument and the type descriptor itself as its second.

The object it designates has the layout of an anonymous struct type whose field types are the types of those entries, in that order. Where the type is not an instantiation of a generic declaration, field 3 designates an immortal object of size zero.

### 9.5.3 Protocol descriptor

A **protocol descriptor** is divided into three zones, in the following order.

#### Zone 1

Zone 1 contains one `%void` field per bound element of the protocol’s bound list, in the order the elements are declared. Each field designates the descriptor that the element designates for the implementing type, as the subclause on bound descriptor emission defines.

#### Zone 2

Zone 2 contains one subroutine pointer field per associated subroutine declared in the protocol body, in declaration order. Where the protocol `impl` block provides the associated subroutine, the subroutine pointer of the body it provides occupies the field, and otherwise the default body’s subroutine pointer occupies it.

#### Zone 3

Zone 3 contains one `%void` field per associated constant declared in the protocol body, in declaration order. Each field designates the object the implementing type gives the constant, and where the implementing type gives none, the object the protocol’s default expression yields with the generic arguments of the `as` clause substituted for the protocol’s generic parameters and the implementing type for `selftype`. That object is a resident object and permits no store.

#### Field indexing

A protocol descriptor holds the fields the three zones give it and no other.

Zone 2 begins at field `S`, where `S` is the number of bound elements. The `k`-th associated subroutine declared in the protocol body, counting from zero, occupies field `S + k`. Zone 3 begins at field `S + M`, where `M` is the number of associated subroutines. The `k`-th associated constant declared in the protocol body occupies field `S + M + k`.

### 9.5.4 Descriptor field signatures

The type of the descriptor field an associated subroutine occupies is the lowered signature of the subroutine as the protocol declares it, as defined in the subclause on signature lowering. A generic parameter of the protocol remains a generic parameter in that lowering, whatever the `impl` block resolves it to. An associated subroutine that a protocol `impl` block provides has that lowered signature.

The type of a zone 3 field of a protocol descriptor is `%void`, whatever the declared type of the associated constant. A load of the constant reads the designated object under that declared type.

For an invocation through a protocol type, the descriptor references of `selftype` are the ones the subclause on protocol types gives. The invocation supplies the descriptor references and the dependence argument values of every generic parameter the protocol and the subroutine declare, and of every subject bound the subroutine carries, determined from the generic arguments the protocol type and the invocation give.

#### Examples (informative)

```
// protocol ord, impl si4 as ord
// Source: fn cmp(&self, other: &selftype) -> ordering
// Field:  fn(%mut void, %void, %void, %void, %void) -> void
//            ^out       ^self  ^other ^tyd   ^prd

// protocol measurable, impl si4 as measurable
// Source: fn width(&self) -> uaddr
// Field:  fn(%mut void, %void, %void, %void) -> void
//            ^out       ^self  ^tyd   ^prd

// protocol clone, impl widget as clone
// Source: fn clone(&self) -> selftype
// Field:  fn(%mut void, %void, %void, %void) -> void
//            ^out       ^self  ^tyd   ^prd

// protocol keyed[K], impl widget as keyed[ui4]
// Source: fn at(&self, key: K) -> uaddr
// Field:  fn(%mut void, %void, %void, %void, %void, %void) -> void
//            ^out       ^self  ^key   ^tyd   ^prd   ^K

// protocol seekable (a parameter naming no generic parameter)
// Source: fn skip(&self, n: uaddr) -> uaddr
// Field:  fn(%mut void, %void, uaddr, %void, %void) -> void
//            ^out       ^self  ^n     ^tyd   ^prd
```

A protocol with no bound list:

```
protocol ord {
    fn cmp(&self, other: &selftype) -> ordering;           // field 0
    fn lt(&self, other: &selftype) -> verdict[void, void]; // field 1
    fn gt(&self, other: &selftype) -> verdict[void, void]; // field 2
}

// Type descriptor for si4 (selftype'bound(type)):
// [0] = 4                 (si4'size)
// [1] = 4                 (si4'align)
// [2] = &no_op_destructor (si4 has no with destruct)
// [3] = &empty            (si4 is not a generic instantiation)

// Protocol descriptor for si4 as ord:
// [0] = &si4_cmp : fn(%mut void, %void, %void, %void, %void) -> void
// [1] = &si4_lt  : fn(%mut void, %void, %void, %void, %void) -> void
// [2] = &si4_gt  : fn(%mut void, %void, %void, %void, %void) -> void
//                     ^out       ^self  ^other ^tyd   ^prd
```

A protocol with a bound list:

```
protocol packet: measurable + clone {
    fn cksum(&self) -> si4;
}

// Protocol descriptor layout for packet:
// [0] = %void → measurable protocol descriptor (zone 1)
// [1] = %void → clone protocol descriptor (zone 1)
// [2] = &cksum : fn(%mut void, %void, %void, %void) -> void (zone 2)
//                   ^out       ^self  ^tyd   ^prd
// measurable and clone add no descriptor parameter: the bound
// upon the implementing type is packet alone.
```

A bound list that names a built-in bound:

```
protocol scaled: measurable + numeric {
    fn scale(&self, by: selftype) -> selftype;
}

// Protocol descriptor layout for scaled:
// [0] = %void → measurable protocol descriptor (zone 1)
// [1] = %void → arithmetic descriptor           (zone 1)
// [2] = &scale : fn(%mut void, %void, %void, %void, %void) -> void
//                   ^out       ^self  ^by    ^tyd   ^prd  (zone 2)
// Dispatch does not follow the numeric field.
```

## 9.6 Protocol types

A **protocol type** is a type whose concrete identity is erased. A protocol type has size zero, is uncopyable, and storage is reserved for no object of the type.

### Syntax

```
protocol_type = "dyn", ws, single_path ;
```

### Static semantics

The stored representation of a reference to a protocol type is three fields in this order:

<table>
<thead><tr><th>Field</th><th>Content</th></tr></thead>
<tbody>
<tr><td><code>ptr</code></td><td>reference to the value</td></tr>
<tr><td><code>tyd</code></td><td><code>%void</code> &mdash; type descriptor</td></tr>
<tr><td><code>prd</code></td><td><code>%void</code> &mdash; protocol descriptor</td></tr>
</tbody>
</table>

The total size is 3 × `(%void)'size`, and the alignment is `(%void)'align`.

The type of `.ptr` is the one the subclause on slice references gives `.ptr` of a slice reference of the same tribe and modifiers whose element type is `void`. `.tyd` and `.prd` are `%void`.

A managed reference decays to a reference to a protocol type, of the same tribe and the same modifiers, where an implementation of the protocol of that protocol type for its referent type is witnessed, as the subclause on `with impl` defines witnessed implementations. The decay constructs a wide reference whose `.ptr` carries the address of the referent of the decayed reference, and whose `.tyd` and `.prd` are those the subclause on bound descriptor emission gives.

### Dynamic semantics

A method invocation on a protocol type is performed in the two stages the subclause on descriptors defines.

Item resolution yields the method the invocation names, the protocol that declares it, and the protocols through which it reached that protocol, as the subclause on name resolution defines.

Selection begins at the descriptor `.prd` carries. For each protocol through which item resolution reached the declaring protocol, in that order, it follows the zone 1 field at the index that protocol’s bound element occupies, and so reaches the descriptor of the protocol that declares the method. It takes the field at the index that declaration assigns the method.

The subroutine pointer is then loaded from that field, and the subroutine it designates is invoked. The self argument is created from the reference the receiver yields, designates the object `.ptr` designates, and is passed as the subclause on signature lowering requires for the self parameter the method bears. The type descriptor argument is `.tyd`, and the protocol descriptor argument is the descriptor selection reached.

### Constraints

A protocol type shall stand only as the referent type of a reference type, whether written or inferred.

A method that takes `self` by value shall not be invoked through a reference to a protocol type.

### Examples (informative)

```
fn print_value(val: &dyn fmt) {
    println("{}", &[val]);
}

let x: si4 = 42;
let b = verdict[void, void]::Pass.{ void };
print_value(&x); // decay: &si4 → &dyn fmt
print_value(&b); // &verdict[void, void] → &dyn fmt

// Heterogeneous collection
let items: [&dyn fmt; 2] = [&x, &b];
let mut iter = items.iter();
while iter.next() -> item {
    println("value: {}", &[item]);
}
```

## 9.7 Built-in bounds

### Syntax

```
builtin_bound = "numeric" | "integer" | "primitive"
              | "copyable" | "variadic" | "atomic"
              | "transact" ;
```

### 9.7.1 `numeric`

#### Static semantics

A closed type satisfies `numeric` if and only if it is an integer type or a floating radix point number type.

### 9.7.2 `integer`

#### Static semantics

A closed type satisfies `integer` if and only if it is an integer type.

### 9.7.3 `primitive`

#### Static semantics

A closed type satisfies `primitive` if and only if it is an unsigned integer type.

### 9.7.4 `copyable`

#### Static semantics

A closed type satisfies `copyable` if and only if it is copyable.

#### Examples (informative)

```
fn duplicate[T: copyable](val: T) -> .{T, T} {
    return .{val, val}; // T is copyable
}

fn store[T](slot: $T, val: T) routes(val -> *slot) {
    *slot = val;
    // T may follow transfer semantics, and val is not accessed after
}
```

### 9.7.5 `variadic`

#### Static semantics

A closed type satisfies `variadic` if and only if it is a struct declared `with variadic`.

### 9.7.6 `atomic`

#### Static semantics

A closed type `T` satisfies `atomic` if and only if `T` is copyable and the atomicity set of each machine on which the satisfaction is required holds the pair of `T'size` and `T'align`, as the clause on semantics defines that set. The satisfaction is required on each machine on which the construct requiring it is analysed, and, where that construct is a type, on each machine on which an expression is analysed whose type is, or has as a constituent, that type.

### 9.7.7 `transact`

#### Static semantics

A closed type `T` satisfies `transact` if and only if `T` is copyable and the transactionality set of each machine on which the satisfaction is required holds the pair of `T'size` and `T'align`, as the clause on semantics defines that set. The satisfaction is required on the machines the subclause on `atomic` defines.
