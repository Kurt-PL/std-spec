# 9. Protocols and implantations

This clause defines protocols and implantations: inherent implantations, implanted subroutines and implanted constants, protocol declarations and implantations, descriptors, protocol types, and the built-in bounds.

## 9.1 Inherent implantations

An `impl` block without an `as` clause is an **inherent `impl` block**. It declares an **inherent implantation** and introduces implanted items into the namespace of each type it is on. An `impl` block with an `as` clause is a **protocol `impl` block**. It declares a **protocol implantation** of the protocol that clause names, and introduces implanted items into the namespace of that implantation for each type it is on. An `impl(...)` parameter list introduces generic parameters into the whole `impl` block, including the target type and the `as` clause.

### Syntax

```
impl_block = "impl", [ ws, impl_generic_params ], ws, type,
             [ ws, "as", ws, single_path ],
             ws, '{', ws, { impl_item, ws }, '}' ;

impl_generic_params = '(', ws, generic_item, ws,
                      { ',', ws, generic_item, ws }, [ ',', ws ],
                      ')' ;

impl_item = { item_decoration, ws },
            ( method_def | implanted_const_def ) ;

implanted_const_def = [ "pub", ws ], "const", ws, identifier, ws,
                      [ ':', ws, type, ws ], '=', ws, expression,
                      ws, ';' ;
```

### Static semantics

An **implanted subroutine** or an **implanted constant** is a subroutine or a constant, respectively, that appears directly in an `impl` block or a protocol body. Either is an **implanted item**. The expression of an implanted constant is the one the `impl` block provides or, where the block provides none, the default expression of the protocol. The identifiers of a default expression are resolved as within the protocol, with the generic arguments of the `as` clause substituted for the protocol’s generic parameters and the target type for `selftype`.

A **parameter anchor** of a parameter of an `impl(...)` parameter list is the target type, or a type argument or dependence argument (§4.10) at any depth of nesting in the target type or in the `as` clause, that is that parameter.

The bound of a parameter of an `impl(...)` parameter list is the bound that list places upon it, followed by the bound elements that each generic declaration places upon the generic parameter that resolves to a parameter anchor of it. The elements of each such declaration are taken with its arguments substituted and in its declaration order (§2.2.6). The parameter anchors are taken in the order they appear in the target type and then in the `as` clause. An element already in the bound is not repeated.

An `impl` block is on a type where its target type is that type, or resolves to it under a resolution of the parameters of its `impl(...)` parameter list in which each argument satisfies the bound of the parameter that resolves to it.

An implanted item to which a path or a method invocation resolves through a type, by the rules of §9.2.1, is taken with the following substitutions:

&mdash; That type for `selftype`.

&mdash; Where an `impl` block provides the item, for each parameter of that block’s `impl(...)` parameter list, the argument it resolves to under the resolution that puts that block on that type.

&mdash; Where a method invocation that carries a generic argument list (§4.10) resolves to the item, for each generic parameter of the item, the argument of that list that corresponds to it.

Where the searches of name resolution reach the item and every path they take to it passes through the same protocol instantiation, the resolution that puts the providing block on the type is also one under which that block’s `as` clause names that instantiation. Where the type, and the protocol instantiation where there is one, leave a parameter of that block’s `impl(...)` parameter list unresolved, that parameter is an omitted argument of the method invocation, or of the path outside a `use_tree`, that resolves to the item.

### Dynamic semantics

The expression of an implanted constant in which no generic parameter occurs free is evaluated at translation time, as §6.11 defines. Any other expression of an implanted constant is not an evaluation root. It is evaluated in the evaluation of each construct that names the implanted constant and does not load it from a protocol descriptor, and once on the machine of each protocol descriptor with a field for that implanted constant, when that descriptor is emitted.

### Constraints

Each parameter of an `impl(...)` parameter list shall have a parameter anchor. In a protocol `impl` block, the `impl(...)` parameter list shall place no bound upon a parameter.

### Examples (informative)

These examples apply where `cellbits::prog == 8`.

```
impl(T) stack[T] {
    // Implanted subroutine: invoked via stack::new()
    pub fn new() -> selftype { ... }

    // Implanted subroutine
    pub fn with_capacity(cap: uaddr) -> selftype { ... }

    // Methods: invoked via value.method()
    pub fn push($mut self, val: T) routes(val -> *...self) { ... }
    pub fn pop($mut self) -> verdict[T, void] { ... }
    pub fn len(&self) -> uaddr { return self.len; }
    pub fn is_empty(&self) -> verdict[void, void] {
        return self.len == 0;
    }
}

impl si4 {
    // Implanted constants: accessed via si4::min, si4::max
    pub const min: si4 = -2147483648;
    pub const max: si4 = 2147483647;
    // type inferred from the expression
    pub const zero = 0~si4;
}

// Usage
let mut s = stack[si4]::new();  // implanted subroutine
s.push(42);                     // method
let m = si4::max;               // implanted constant
```

## 9.2 Implanted subroutines and name resolution

### Syntax

```
method_def          = subroutine_def_header, ws, '(', ws,
                      [ method_params, ws ], ')',
                      subroutine_sig_tail, ws, block ;

subroutine_proto    = subroutine_proto_header, ws, '(', ws,
                      [ subroutine_proto_params, ws ], ')',
                      subroutine_sig_tail, ws, ';' ;

method_params       = self_param, [ ws, ',', ws, [ parameter_list ] ]
                    | parameter_list ;

subroutine_proto_params = self_param,
                      [ ws, ',', ws, [ proto_parameter_list ] ]
                    | proto_parameter_list ;

self_param          = ( '&' | '$' | '%' ), ws, { ref_modifier, ws },
                      ( "self" | '[', ws, "self", ws, ']' )
                    | [ "mut", ws ], "self" ;
```

### Static semantics

An implanted subroutine is invoked through a path expression or through a name that stands for the path of one. An implanted subroutine that carries a self parameter is a **method**, and is invoked through the `.` operator as well.

`selftype` is a keyword that stands, as a path segment, for a type the enclosing declaration fixes as follows:

&mdash; An `impl` block &mdash; its target type, from the point where that type is written to the end of the block. Where the block carries an `as` clause, `selftype` is, for signature lowering alone, a type parameter (§4.10) of every subroutine the block provides, and the bound upon it there is the protocol the `as` clause names.

&mdash; A `protocol` declaration &mdash; the target type of each implantation of the protocol, throughout the declaration. `selftype` is a type parameter of every item the protocol declares, preceding every type parameter the item declares, and the bound upon it is the protocol that declares the item.

&mdash; A `struct`, `enum`, or `contract` declaration &mdash; the type the declaration introduces, with its own generic parameters as the generic arguments.

Where the type that the enclosing declaration fixes for `selftype` is an instantiation of a `struct`, `enum`, or `contract` declaration, `selftype` takes generic arguments as the name of that declaration does, and then stands for the instantiation of that declaration they give.

The `self_param` forms are:

&mdash; `self` and `mut self` &mdash; equivalent respectively to `self: selftype` and to `mut self: selftype`.

&mdash; `X self` and `X[self]`, where `X` combines a tribe with any permitted modifiers &mdash; equivalent respectively to `self: X selftype` and to `self: X[selftype]`.

### Constraints

A `selftype` shall carry generic arguments only where the type that the enclosing declaration fixes for it is an instantiation of a `struct`, `enum`, or `contract` declaration.

### Design rationale (informative)

Brackets without a length occur only in a slice reference, which a tribe leads. The bracketed forms therefore require a tribe.

### Examples (informative)

```
impl(T) T {
    fn at(&[self], idx: uaddr) -> &selftype {
        // self: &[T]
        ...
    }

    fn at_xcl($mut [self], idx: uaddr) -> $mut selftype {
        // self: $mut [T]
        ...
    }
}
```

### 9.2.1 Name resolution

#### Static semantics

Where, in a method invocation `e.m(args)`, the type of `e` after reference transparency is a protocol type, that protocol is searched. A search of a protocol reaches the method named `m` that the protocol declares, and, where the protocol declares no method named `m`, proceeds through the protocols its bound list names, in declaration order, each searched by this rule.

The number of protocol instantiations having methods named `m` that the searches for the invocation reach decides the invocation:

&mdash; Exactly one protocol instantiation &mdash; the invocation resolves to the method named `m` of that instantiation, by the first path the searches take.

&mdash; Two or more protocol instantiations &mdash; the invocation is ambiguous.

&mdash; None &mdash; the invocation resolves to no method.

Where the type of `e` after reference transparency is a protocol type or a type parameter, and a search for the invocation reaches a method whose self parameter is bracketed, the invocation resolves to no method. Where the search for a protocol type reaches a method whose signature mentions `selftype` other than as the referent type of the type of its self parameter, the invocation resolves to no method. Where it reaches any other method, `selftype` stands for that protocol type for that invocation.

Where the type of `e` after reference transparency is an array type, and either it is the referent type of a slice reference or the procedure that follows, applied to it, resolves to no method, the invocation resolves by that procedure applied to its element type (§4.10), under which only a method whose self parameter is bracketed resolves. Under every other application of that procedure, only a method whose self parameter is not bracketed resolves.

For every other type, a method invocation `e.m(args)` is resolved by the following procedure, applied to that type:

1. If an inherent `impl` block on the type provides a method named `m`, the invocation resolves to the method.
2. Otherwise, the protocols of the implantations witnessed (§9.4.2) for the type are searched. Where the searches reach methods named `m`, and all of them belong to implantations that a single `impl` block declares for the type, the invocation resolves to the method named `m` of that block. Where those methods belong to implantations that two or more `impl` blocks declare, the invocation is ambiguous. Where the searches reach no method named `m`, the invocation resolves to no method. Where the type is a type parameter, the number of protocol instantiations having methods named `m` that the searches reach decides the invocation in place of the `impl` blocks, as for the searches of a protocol type.

A qualified method invocation (§6.3.3) `(e impl Protocol).m(args)` is resolved as `e.m(args)` is, as if no inherent `impl` block provided, and no protocol other than `Protocol` declared, a method named `m`.

A path `Type::item` that names an implanted item is resolved as a method invocation upon a value of that type is resolved, with the implanted item in place of the method. A path `(Type impl Protocol)::item` is resolved as `Type::item` is, as if no inherent `impl` block provided, and no protocol other than `Protocol` declared, an implanted item named `item`.

#### Constraints

An invocation or access that is ambiguous, or that resolves to no method or no implanted item, shall not appear.

#### Examples (informative)

```
// Inherent method takes priority over protocol method
struct counter { val: ui4 }

impl counter {
    pub fn get(&self) -> ui4 { return self.val; }
}

protocol readable {
    fn get(&self) -> ui4;
}

impl counter as readable {
    fn get(&self) -> ui4 { return self.val * 2; }
}

let c = counter.{ .val = 5 };
c.get();                 // resolves to inherent: yields 5
(c impl readable).get(); // resolves through readable: yields 10

// Single protocol method, no inherent
struct widget;

protocol drawable { fn draw(&self); }

impl widget as drawable {
    fn draw(&self) { ... }
}

let w = widget;
w.draw(); // resolves to draw of drawable
```

```
// Two protocol methods, no inherent
struct gadget;
protocol render { fn draw(&self); }
protocol paint  { fn draw(&self); }

impl gadget as render { fn draw(&self) { ... } }
impl gadget as paint  { fn draw(&self) { ... } }

let g = gadget;
// g.draw();            // translation failure: ambiguous
(g impl render).draw(); // OK
(g impl paint).draw();  // OK
```

## 9.3 Protocol declarations

### Syntax

```
protocol_decl = [ "pub", ws ], "protocol", ws, identifier,
                [ ws, generic_clause ],
                [ ws, ':', ws, bound ],
                ws, '{', ws, { protocol_item, ws }, '}' ;

protocol_item = { item_decoration, ws },
                ( subroutine_proto | default_subroutine
                | implanted_const ) ;

default_subroutine = method_def ;
implanted_const = [ "pub", ws ], "const", ws, identifier, ws, ':',
                  ws, type, [ ws, '=', ws, expression ], ws, ';' ;
```

### Static semantics

A protocol body contains zero or more **protocol items**: subroutine prototypes (§4.2), default protocol subroutines, and implanted constants. The protocol items of a protocol, and those of each protocol its bound list names, are introduced into its body. Within a protocol body, an identifier that resolves to a name that denotes a protocol item is the same construct as the path `selftype::` followed by that identifier.

#### Protocol congruence

In comparing two protocol declarations on a machine, corresponding generic parameters of the declarations, and corresponding generic parameters of the implanted subroutines they declare, are taken to be the same generic parameter, and the `selftype` of the one and that of the other to be the same type. Where the two are of different translation units, a requirement of the comparison that two types be the same is a requirement that they be compatible (§10.10.2) on that machine. Two bound elements naming declared protocols agree where those declarations are congruent on that machine and their generic arguments are the same. Two bound elements naming built-in bounds agree where they name the same bound. Two subject bounds (§9.4.2) agree where their subjects are the same and their protocols agree. One protocol declaration is **congruent** with another on a machine where all of the following hold.

&mdash; Generic parameters &mdash; the two declare the same number of generic parameters, and corresponding parameters, in declaration order, are of the same kind. Corresponding dependence parameters (§4.10) bear the same type. Corresponding type parameters bear the same number of bound elements, and their corresponding elements, in the order of the bound, agree.

&mdash; Bound elements &mdash; the two declare the same number of bound elements, and corresponding elements agree, in declaration order.

&mdash; Implanted subroutines &mdash; the two declare the same number of implanted subroutines. Corresponding subroutines, in declaration order, bear the following, the same in each:

&nbsp;&nbsp;&mdash; The airside status.

&nbsp;&nbsp;&mdash; The invocation interface.

&nbsp;&nbsp;&mdash; The variadic status.

&nbsp;&nbsp;&mdash; The number of generic parameters, with corresponding parameters, in order, satisfying what the item on generic parameters requires.

&nbsp;&nbsp;&mdash; The type of the self parameter.

&nbsp;&nbsp;&mdash; The parameter types, in order.

&nbsp;&nbsp;&mdash; The return type or `!`.

&nbsp;&nbsp;&mdash; The routes (§8.1.2).

&nbsp;&nbsp;&mdash; The number of subject bounds, with corresponding subject bounds, in order, agreeing.

&mdash; Implanted constants &mdash; the two declare the same number of implanted constants, and corresponding constants bear the same type, in declaration order.

A descriptor emitted under one declaration is a descriptor under every declaration congruent with it on the machine of that descriptor.

As `#extern` permits, a translation unit other than the one that emitted a descriptor can receive it. Where the receiving unit’s declaration is not congruent with the emitting unit’s declaration on the machine of the descriptor, an access through the descriptor can cause indeterminate state.

### Examples (informative)

```
pub protocol bounded: copyable {
    const min: selftype;
    const max: selftype;
}

impl ui1 as bounded {
    const min: ui1 = 0;
    const max: ui1 = !0~ui1;
}

fn clamp[T: bounded + primitive](val: T) -> T {
    let lo = (T impl bounded)::min;
    let hi = (T impl bounded)::max;
    return if val < lo then lo else if val > hi then hi else val;
}
```

### 9.3.1 The bound upon a protocol

#### Static semantics

A protocol **entails** each bound element its bound list names and each bound element that a protocol its bound list names entails.

#### Constraints

A protocol shall not entail a bound element that names it.

#### Examples (informative)

```
pub protocol printable: fmt + clone {
    fn print(&self) { print_value(self); } // print_value as in §9.6
}
```

### 9.3.2 Default protocol subroutines

#### Static semantics

A **default protocol subroutine** is a protocol item whose declaration stands in the protocol body with its body present. Where a protocol `impl` block of the protocol does not provide the item, that body is used in the implantation that the block declares. Where the block provides it, the provided body replaces the default entirely.

#### Examples (informative)

```
pub protocol encodable {
    fn name(&self) -> &[ui1];

    fn encode(&self, out: $mut [ui1]) -> verdict[uaddr, &[ui1]] {
        // invokes the subroutine prototype
        return verdict::Fail.{ self.name() };
    }
}
```

## 9.4 Protocol implantations

### Constraints

Every subroutine prototype declared in the protocol shall be provided. An implanted constant shall be provided unless the protocol provides a default expression for it. A protocol `impl` block shall provide only items the protocol declares.

An implanted subroutine a protocol `impl` block provides shall state the following as the protocol declares them, in the same order:

&mdash; The airside status.

&mdash; The invocation interface.

&mdash; The variadic status.

&mdash; The generic clause.

&mdash; The type of the self parameter.

&mdash; Each parameter type.

&mdash; The return type or `!`.

&mdash; The subject bounds.

In each of them, the generic arguments of the `as` clause are substituted for the protocol’s generic parameters, and the target type for `selftype`. The subroutine shall have the same routes (§8.1.2) as the protocol’s declaration of it. An implanted constant a protocol `impl` block provides shall bear the type the protocol declares for it, with the same substitutions.

The target type shall satisfy each bound element that the bound list of the protocol names, with the generic arguments of the `as` clause substituted for the protocol’s generic parameters. Where the protocol `impl` block carries an `impl(...)` parameter list, the target type shall satisfy those bound elements under each resolution of the parameters of that list in which each argument satisfies the bound of the parameter that resolves to it.

### Examples (informative)

```
impl si4 as ord {
    fn cmp(&self, other: &selftype) -> ordering {
        return if *self > *other then ordering::greater
        else if *self < *other then ordering::less
        else ordering::equal;
    }
}

impl vec[si4] as iterator[si4] {
    fn next($mut self) -> verdict[si4, void] {
        if self.pos < self.len {
            let val = *self.data.at(self.pos);
            self.pos += 1;
            return verdict::Pass.{ val };
        } else {
            return verdict::Fail.{ void };
        }
    }
}
```

### 9.4.1 Duplicate detection

#### Static semantics

A translation unit emits, for each machine, at most one protocol descriptor for each implantation of a protocol instantiation for a type within it, and the zone 2 fields of each designate the bodies found in that unit.

#### Constraints

At most one `impl` block shall declare an implantation of a given protocol instantiation for a type within the same translation unit. Instantiations that resolve the protocol’s generic parameters differently are distinct.

#### Implementation requirements

The diagnostic for two implantations of one protocol instantiation shall identify both and a source unit from which both are reached in the `#add` dependency graph.

### 9.4.2 `with impl`

#### Syntax

```
subject_bound = "impl", ws, type, ws, "as", ws, single_path ;
```

#### Static semantics

A `with impl` item is a **subject bound**. It stands in the `with` clause of a subroutine definition, of the definition of an implanted subroutine, of a subroutine prototype, or of a subroutine pointer type. The type it names before `as` is its **subject**, and the protocol its `single_path` names is its protocol.

Where a type is a closed type (§4.10) and no generic parameter occurs free in a generic argument of a protocol, every implantation of that protocol for that type is **witnessed** everywhere. Otherwise, the implantations witnessed within a construct are the following.

&mdash; The implantations a bound upon a type parameter names for that type parameter.

&mdash; Within a subroutine declaration, the implantations its subject bounds name for their subjects.

&mdash; Within a protocol `impl` block, the implantation the block provides for its target type.

&mdash; For each implantation witnessed, the implantations for the same type of the protocols the bound list of its protocol names, with the generic arguments of its protocol substituted.

Where a rule names no construct, the construct is the one that rule applies to. A protocol descriptor is emitted only for an implantation witnessed where it is emitted.

At each invocation of a subroutine, each generic parameter that occurs free in a subject bound of it is replaced, in that bound, by the argument to which it resolves. For each subject bound so substituted, the invoker supplies an implantation of the protocol for the subject that is witnessed within the invoker.

#### Constraints

Except within the signature of an implanted subroutine that a protocol `impl` block provides, each of the following shall hold of a subject bound:

&mdash; A generic parameter occurs free in its subject or in a generic argument of its protocol.

&mdash; Its subject is not a type parameter.

&mdash; No other subject bound of the same declaration bears the same subject and the same protocol instantiation.

`selftype` shall not occur free in the subject of a subject bound of an implanted subroutine that a protocol body declares, or in a generic argument of its protocol.

An invocation whose invoker cannot supply a witnessed implantation for a subject bound, or for a bound element of a type parameter that names a declared protocol, shall not appear.

## 9.5 Descriptors

A **descriptor** is an object that the implementation emits for a type. The type of a reference to a descriptor is `%void`.

§9.5.1 to §9.5.3 each give the fields of one kind of descriptor, in order. Kurt standard alignment, applied to that sequence of field types, gives the size and the alignment of the descriptor and the offset of each field. A descriptor belongs to a machine (§6.13.2). A field type whose width derives from the cell width (§2.2.1) takes the cell width of that machine.

A protocol item is reached through a descriptor in two stages. **Item resolution** takes an identifier to the item it names within the declaration found in the translation unit, to the protocol that declares it, and to the protocols through which it reached that protocol, as §9.2.1 defines. **Field lookup** then starts at the descriptor through which the item is reached. For each of those protocols in turn, it follows the zone 1 field at the index of its bound element. It then takes the field at the index the declaring protocol’s declaration order assigns the item.

Where the type is not an instantiation of a generic declaration, field 3 designates an immortal object (§2.2.6) of size zero.

### 9.5.3 Protocol descriptor

A **protocol descriptor** is divided into three zones, in the following order.

#### Zone 1

Zone 1 contains one `%void` field per bound element of the protocol’s bound list, in declaration order. Each field designates the descriptor emitted for the element and the type that the protocol descriptor describes, as §6.13.2 defines.

#### Zone 2

Zone 2 contains one subroutine pointer field per implanted subroutine declared in the protocol body, in declaration order. Where the protocol `impl` block provides the implanted subroutine, the subroutine pointer of the body it provides occupies the field, and otherwise the default body’s subroutine pointer occupies it.

#### Zone 3

Zone 3 contains one `%void` field per implanted constant declared in the protocol body, in declaration order. Each field designates the object that the expression of that implanted constant yields for the type that the protocol descriptor describes. That object is a resident object (§2.2.6) and permits no store.

#### Field indexing

Zone 2 begins at field *S*, where *S* is the number of bound elements. The *k*-th implanted subroutine declared in the protocol body, counting from zero, occupies field *S* + *k*. Zone 3 begins at field *S* + *M*, where *M* is the number of implanted subroutines. The *k*-th implanted constant declared in the protocol body occupies field *S* + *M* + *k*.

### 9.5.4 Descriptor field signatures

The type of the descriptor field an implanted subroutine occupies is the lowered signature (§4.10.2) of the subroutine as the protocol declares it. A generic parameter of the protocol remains a generic parameter in that lowering. An implanted subroutine that a protocol `impl` block provides has that lowered signature.

A load of an implanted constant is a load, at the declared type of that constant, of the object that the field it occupies designates.

For an invocation through a protocol type, the descriptor references of `selftype` are the ones §9.6 gives. From the generic arguments the protocol type and the invocation give, the invocation supplies the descriptor references and the dependence argument values of every generic parameter the protocol and the subroutine declare, and the descriptor references of every subject bound the subroutine carries.

#### Examples (informative)

```
// protocol ord, impl si4 as ord
// Source: fn cmp(&self, other: &selftype) -> ordering
// Field:  fn(%mut void, %void, %void, %void, %void) -> void
//            ^out       ^self  ^other ^tyd   ^prd

// protocol measurable, impl si4 as measurable
// Source: fn width(&self) -> uaddr
// Field:  fn(%mut void, %void, %void, %void) -> void
//            ^out       ^self  ^tyd   ^prd

// protocol clone, impl widget as clone
// Source: fn clone(&self) -> selftype
// Field:  fn(%mut void, %void, %void, %void) -> void
//            ^out       ^self  ^tyd   ^prd

// protocol keyed[K], impl widget as keyed[ui4]
// Source: fn at(&self, key: K) -> uaddr
// Field:  fn(%mut void, %void, %void, %void, %void, %void) -> void
//            ^out       ^self  ^key   ^tyd   ^prd   ^K

// protocol seekable (a parameter naming no generic parameter)
// Source: fn skip(&self, n: uaddr) -> uaddr
// Field:  fn(%mut void, %void, uaddr, %void, %void) -> void
//            ^out       ^self  ^n     ^tyd   ^prd
```

A protocol with no bound list:

```
protocol ord {
    fn cmp(&self, other: &selftype) -> ordering;           // field 0
    fn lt(&self, other: &selftype) -> verdict[void, void]; // field 1
    fn gt(&self, other: &selftype) -> verdict[void, void]; // field 2
}

// Type descriptor for si4 (selftype'bound(type)):
// [0] = 4                 (si4'size)
// [1] = 4                 (si4'align)
// [2] = &no_op_destructor (si4 has no with destruct)
// [3] = &empty            (si4 is not a generic instantiation)

// Protocol descriptor for si4 as ord:
// [0] = &si4_cmp : fn(%mut void, %void, %void, %void, %void) -> void
// [1] = &si4_lt  : fn(%mut void, %void, %void, %void, %void) -> void
// [2] = &si4_gt  : fn(%mut void, %void, %void, %void, %void) -> void
//                     ^out       ^self  ^other ^tyd   ^prd
```

A protocol with a bound list:

```
protocol packet: measurable + clone {
    fn cksum(&self) -> si4;
}

// Protocol descriptor layout for packet:
// [0] = %void → measurable protocol descriptor (zone 1)
// [1] = %void → clone protocol descriptor      (zone 1)
// [2] = &cksum : fn(%mut void, %void, %void, %void) -> void (zone 2)
//                   ^out       ^self  ^tyd   ^prd
// measurable and clone add no descriptor parameter: the bound
// upon the type the descriptor describes is packet alone.
```

A bound list that names a built-in bound:

```
protocol scaled: measurable + numeric {
    fn scale(&self, by: selftype) -> selftype;
}

// Protocol descriptor layout for scaled:
// [0] = %void → measurable protocol descriptor (zone 1)
// [1] = %void → arithmetic descriptor          (zone 1)
// [2] = &scale : fn(%mut void, %void, %void, %void, %void) -> void
//                   ^out       ^self  ^by    ^tyd   ^prd  (zone 2)
```

## 9.6 Protocol types

A **protocol type** is a type whose concrete identity is erased. A protocol type has size zero, is uncopyable, and storage is reserved for no object of the type.

### Syntax

```
protocol_type = "dyn", ws, single_path ;
```

### Static semantics

The stored representation of a reference to a protocol type is three fields in this order:

<table>
<thead><tr><th>Field</th><th>Content</th></tr></thead>
<tbody>
<tr><td><code>ptr</code></td><td>reference to the value</td></tr>
<tr><td><code>tyd</code></td><td><code>%void</code> &mdash; type descriptor</td></tr>
<tr><td><code>prd</code></td><td><code>%void</code> &mdash; protocol descriptor</td></tr>
</tbody>
</table>

Kurt standard alignment gives the size and the alignment of the reference, and the offset of each field, from the types of those fields in that order.

The type of `.ptr` is the one §8.2.5 gives `.ptr` of a slice reference of the same tribe and modifiers whose element type is `void`. `.tyd` and `.prd` are `airside` fields of type `%void`.

A managed reference other than a wide reference decays to a reference to a protocol type, of the same tribe and the same modifiers, where an implantation of the protocol of that protocol type for its referent type is witnessed. The decay constructs a wide reference with the following fields:

&mdash; `.ptr` carries the address of the referent of the decayed reference.

&mdash; `.tyd` designates the type descriptor of the referent type of that reference.

&mdash; `.prd` designates the protocol descriptor of the implantation of that protocol witnessed for that referent type.

Both descriptors are immortal objects.

### Dynamic semantics

A method invocation through a protocol type is performed in the two stages §9.5 defines.

Field lookup begins at the descriptor `.prd` carries.

The subroutine pointer is then loaded from that field, and the subroutine it designates is invoked. The invocation stores into the object of the self parameter, in place of the value of the first argument, a reference with the address that `.ptr` carries. The reference type through which it performs that store has the tribe and modifiers of the type of the self parameter, and the erased type (§8.2.2) as its referent type. The type descriptor argument is `.tyd`. The protocol descriptor argument is the descriptor that field lookup yields.

### Constraints

A protocol type that is written or inferred shall stand, before any substitution of generic arguments, only as the referent type of a reference type.

### Examples (informative)

```
fn print_value(val: &dyn fmt) {
    println("{}", &[val]);
}

let x: si4 = 42;
let b = verdict[void, void]::Pass.{ void };
print_value(&x); // decay: &si4 → &dyn fmt
print_value(&b); // &verdict[void, void] → &dyn fmt

// Heterogeneous collection
let items: [&dyn fmt; 2] = [&x, &b];
let mut iter = items.iter();
while iter.next() -> item {
    println("value: {}", &[item]);
}
```

## 9.7 Built-in bounds

### Syntax

```
builtin_bound = "numeric" | "integer" | "primitive"
              | "copyable" | "variadic" | "atomic"
              | "transact" ;
```

### 9.7.1 `numeric`

#### Static semantics

A closed type satisfies `numeric` if and only if it is an integer type or a floating radix point number type.

### 9.7.2 `integer`

#### Static semantics

A closed type satisfies `integer` if and only if it is an integer type.

### 9.7.3 `primitive`

#### Static semantics

A closed type satisfies `primitive` if and only if it is an unsigned integer type.

### 9.7.4 `copyable`

#### Static semantics

A closed type satisfies `copyable` if and only if it is copyable.

#### Examples (informative)

```
fn duplicate[T: copyable](val: T) -> .{T, T} {
    return .{val, val}; // T is copyable
}

fn store[T](slot: $mut T, val: T) routes(val -> *slot) {
    *slot = val;
    // T may follow transfer semantics, and val is not accessed after
}
```

### 9.7.5 `variadic`

#### Static semantics

A closed type satisfies `variadic` if and only if it is a struct declared `with variadic`.

### 9.7.6 `atomic`

#### Static semantics

A closed type `T` satisfies `atomic` if and only if `T` is copyable and the atomicity set (§2.1) of each machine on which the satisfaction is required holds a pair whose size is `T'size` and whose alignment is zero or divides `T'align`. The satisfaction is required on each machine on which the construct requiring it is analysed. Where that construct is a type, it is required also on each machine on which an expression whose type is, or has as a constituent, that type is analysed. Where the construct is a `T'bound(atomic)` or `T'bound(transact)` expression, the atomicity set, the transactionality set, and the size and alignment of `T` are those of the machine the evaluation takes them from, as §6.11.1 defines, or, in a qualified form, of the machine the qualifier names.

### 9.7.7 `transact`

#### Static semantics

A closed type `T` satisfies `transact` if and only if `T` is copyable and the transactionality set (§2.1) of each machine on which the satisfaction is required holds a pair whose size is `T'size` and whose alignment is zero or divides `T'align`. The satisfaction is required on the machines §9.7.6 defines.
